== V2Ray原理讲解

=== 核心概念

V2Ray 是一个模块化的代理平台, 提供网络流量转发、路由和加密功能. 它不是一个单一的协议, 而是一个**框架**, 支持多种代理协议(VMess, Shadowsocks, HTTP, SOCKS 等)并允许通过高度灵活的配置组合来实现复杂的网络策略.

重点是, V2Ray 的核心**不依赖于特定的加密协议**, 而是通过 **VMess** 协议(一个专属的加密传输协议)来确保通信的机密性和完整性. 同时它引入了 **传输层配置(Transport Layer)**, 可以对流量进行进一步的伪装(mTLS, WebSocket, HTTP/2 等).

=== 核心架构

V2Ray 的架构由几个关键模块组成:

* **Inbound (入站):** 接收来自本地或远程的流量, 支持的协议包括 VMess, Shadowsocks, SOCKS, HTTP, Dokodemo-door(透明代理)等.

* **Outbound (出站):** 将经过处理后的流量发往目标, 支持的协议包括 VMess, Shadowsocks, Freedom, Blackhole 等.

* **Routing (路由):** 流量分发核心, 根据域名、IP、端口、协议类型等规则, 决定将流量发送到哪一个出站. 这是 V2Ray 实现 **智能代理(Fake DNS + 规则分流)** 的基础.

* **Transport (传输层):** 配置数据在客户端和服务器之间如何"传输", 包括 TCP, mKCP, WebSocket, HTTP/2, QUIC 等. 传输层可以在 TLS 上运行, 也可以不加密(裸传输).

* **Policy (策略):** 控制每个用户/连接的握手超时、连接空闲超时、缓冲大小等策略.

* **DNS:** 内置 DNS 客户端, 支持 DNS-over-HTTPS (DoH) 和 DNS-over-TLS (DoT), 用于 Fake DNS 模式和域名解析.

* **Fallback (回落):** 当入站无法处理某个连接时(比如探测到非 VMess 流量), 可以将其 **fallback** 到一个标准的 Web 服务器, 实现伪装.

=== VMess 协议原理

VMess 是 V2Ray 专属的加密传输协议, 设计目标是防止流量特征被深度包检测(DPI)识别.

. **身份认证:** 客户端使用 **UUID (User ID)** 作为身份标识, 服务器同样配置该 UUID 以验证连接. UUID 是一个 128 位的随机标识符, 可以生成多个.

. **加密:** VMess 使用 **AES-256-CFB** 或 **ChaCha20-Poly1305** 等对称加密算法加密数据. 加密密钥由客户端生成的一次性随机数(Nonce)和用户 UUID 通过 KDF 推导得出.

. **抗重放攻击:** 每个连接使用不同的 **Request ID (一次性随机数)** , 服务器会记录最近使用过的 Request ID, 防止攻击者截获并重放数据包.

. **协议混淆:** VMess 数据包在建立连接时包含一个 **响应认证头(Response Authentication Header)** , 客户端在收到响应时需要验证这个头部, 否则丢弃连接. 这使得主动探测变得更加困难.

. **时间验证:** VMess 要求客户端和服务器的时间误差在合理范围内(通常 120 秒). 如果时间偏差过大, 服务器会拒绝连接, 防止时间同步攻击.

=== V2Ray 工作流程

当 V2Ray 代理一个网络请求时, 典型的处理流程如下:

. **入站接收:** 本地 V2Ray 客户端(Inbound)接收到浏览器或其他应用发出的请求(如 HTTP 请求访问 example.com).

. **路由判断:** Routing 模块根据预设规则判断该流量应该走哪个出站. 例如:
   * 国内网站直接走 Freedom(直连).
   * 被屏蔽的网站走 VMess 出站(通过远程服务器转发).

. **传输层封装:** 根据 Outbound 配置, 将数据通过 Transport 层进行特定的封装. 例如:
   * 使用 WebSocket + TLS 将 VMess 数据伪装成 HTTPS 流量.
   * 使用 mKCP 在 UDP 上传输以提高速度.

. **加密发送:** 数据经过 VMess 加密后, 通过远程服务器(Inbound)接收并解密, 然后由远程服务器向真正的目标(example.com)发出请求.

. **返回响应:** 远程服务器获取响应后, 同样加密后通过 Transport 传回本地客户端, 最终返回给浏览器.

=== 关键特性详解

==== 传输层 (Transport)

V2Ray 的传输层是其最强大的功能之一, 它使得流量可以以多种形态出现在网络上:

* **TCP:** 默认传输方式, 支持头部伪装(HTTP 伪装头).

* **mKCP:** 基于 KCP 协议的 UDP 传输, 通过牺牲部分带宽换取更低延迟, 适用于高丢包环境.

* **WebSocket:** 将流量包装在 WebSocket 帧中, 可以配合 CDN(Cloudflare 等)部署, 实现 IP 隐藏.

* **HTTP/2:** 将流量封装在 HTTP/2 流中, 利用 HTTP/2 的多路复用特性减少连接数.

* **QUIC:** 基于 UDP 的新一代传输协议, 提供更快的连接建立(0-RTT)和更好的拥塞控制.

==== 路由策略 (Routing)

* **域名规则:** 支持全匹配、正则匹配、子域名匹配. 内置常用的 geoip.dat 和 geosite.dat 数据库, 提供按地理区域或网站分类的规则.

* **协议规则:** 可以根据流量类型(如 HTTP、Bittorrent)进行分流.

* **Fake DNS:** 一种特殊的 DNS 策略, 拦截 DNS 请求并返回假 IP, 随后根据这个假 IP 将流量正确路由, 避免重复 DNS 解析.

==== Fallback (回落机制)

V2Ray 的 fallback 是一个巧妙的伪装特性:

. 代理服务器在同一个端口上监听.

. 当检测到非代理流量(比如别人直接访问了你的 IP:443)时, 会将该连接 fallback 到一个正常的 Web 服务(如 Nginx 或静态页面).

. 这使得代理服务器看起来像是一个普通的 Web 服务器, 增加了被检测的难度.

==== 多路复用 (Mux)

Mux 允许多个 TCP 连接共享同一个 VMess 连接, 减少握手开销. 配置 `"mux": {"enabled": true, "concurrency": 8}` 可以让最多 8 个连接共享一个隧道.

=== Xray 与 V2Ray 的关系

Xray 是 V2Ray 的一个社区分支, 在 V2Ray 核心功能基础上做了以下增强:

* **XTLS (Xray TLS):** 一种新型传输协议, 在 TLS 握手时"流式"读取数据, 减少解密开销, 显著提升性能.

* **VLESS (VMess-LESS):** 精简版 VMess, 去除了 VMess 的加密层, 依赖底层 TLS 传输加密, 减少计算开销.

* **FQDN (Fully Qualified Domain Name) 路由:** 支持域名在入站中直接匹配, 无需先做 DNS 解析.

目前 Xray 已经成为主流, V2Ray 官方项目基本停止更新. 大多数新特性(如 XTLS、VLESS)仅在 Xray 中可用.

=== 配置示例

以下是一个 V2Ray 客户端的核心配置示例:

[source, json]
----
{
  "inbounds": [
    {
      "port": 1080,
      "protocol": "socks",
      "settings": {
        "auth": "noauth",
        "udp": true
      }
    }
  ],
  "outbounds": [
    {
      "protocol": "vmess",
      "settings": {
        "vnext": [
          {
            "address": "your-server.com",
            "port": 443,
            "users": [
              {
                "id": "uuid-here-xxxx-xxxx-xxxx",
                "alterId": 0,
                "security": "auto"
              }
            ]
          }
        ]
      },
      "streamSettings": {
        "network": "ws",
        "wsSettings": {
          "path": "/websocket-path"
        },
        "security": "tls"
      }
    },
    {
      "protocol": "freedom",
      "tag": "direct"
    },
    {
      "protocol": "blackhole",
      "tag": "blocked"
    }
  ],
  "routing": {
    "domainStrategy": "IPIfNonMatch",
    "rules": [
      {
        "type": "field",
        "domain": [
          "geosite:cn",
          "geosite:category-ads"
        ],
        "outboundTag": "direct"
      },
      {
        "type": "field",
        "ip": ["geoip:cn", "geoip:private"],
        "outboundTag": "direct"
      }
    ]
  }
}
----

=== 总结

* V2Ray 是一个**模块化代理平台**, 核心价值在于灵活的流量路由和传输层伪装能力.

* **VMess** 是其专属加密协议, 通过 UUID、一次性随机数和时效验证保障传输安全.

* **传输层多样性**(TCP, mKCP, WebSocket, HTTP/2, QUIC) 使其可以适应不同网络环境, 配合 CDN 可实现 IP 隐藏.

* **路由规则** 配合 geoip/geosite 数据库, 实现智能分流(国内直连 + 国外代理).

* **Fallback** 机制使代理服务器可以伪装成普通 Web 服务器, 抵抗主动探测.

* 目前 **Xray** 社区分支已继承并超越原 V2Ray, 引入了 XTLS 和 VLESS 等新协议, 成为主流选择.
