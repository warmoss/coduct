== CIDR原理讲解

=== 为什么需要CIDR?

要理解CIDR, 首先要明白它出现之前的问题.

在CIDR出现之前, 互联网使用 **有类别的IP地址**(Classful Addressing), 即A、B、C类地址:

* **A类:** 前8位是网络号, 后24位是主机号. 范围: 1.0.0.0 - 126.0.0.0. 一个A类网络有约1677万台主机, 非常浪费.

* **B类:** 前16位是网络号, 后16位是主机号. 范围: 128.0.0.0 - 191.255.0.0. 一个B类网络有65534台主机, 对于大多数公司来说还是太大.

* **C类:** 前24位是网络号, 后8位是主机号. 范围: 192.0.0.0 - 223.255.255.0. 一个C类网络只有254台主机, 对于稍大的公司又不够用.

**有类别寻址的缺点:**

. **地址浪费严重:** 一个需要300台主机的公司只能申请一个B类地址, 但实际只用了300个, 浪费了6万多个地址.

. **路由表爆炸:** 随着网络数量激增, 路由器需要维护的路由表条目变得非常庞大, 影响了互联网的扩展性.

CIDR就是为了解决这两个核心问题而诞生的.

=== CIDR是什么?

**CIDR**, 全称是 **无类别域间路由**. 它的核心思想就体现在"**无类别**"这三个字上.

* **有类别:** IP地址属于A、B、C哪一类是固定的, 网络号和主机号的分界线由IP地址的前几位决定.

* **无类别:** **打破A、B、C类的固定边界**, 网络号和主机号的分界线可以出现在任意位置, 而不仅仅是8、16、24位.

这个灵活的分界线, 就是通过 **子网掩码** 来定义的.

=== CIDR的核心原理

==== 可变长子网掩码

CIDR使用一个 **前缀** 来表示网络号部分的长度, 这个前缀写在IP地址后面, 用斜杠 `/` 表示.

**格式:** `IP地址 / 前缀长度`

* **前缀长度:** 表示IP地址中, 从左到右有多少位是 **网络位**.

* **剩余位数:** 32 - 前缀长度 = **主机位** 的数量.

**举个例子:** `192.168.1.0/24`

* 这是我们最常见的写法.

* 前缀长度是24, 意味着前24位是网络位.

* 子网掩码就是255.255.255.0(24个1, 后面跟8个0).

* 主机位有32-24=8位, 所以这个网络可以有 2^8 - 2 = 254个可用主机地址(减去网络地址和广播地址).

**再举一个灵活的:** `192.168.1.0/26`

* 前缀长度是26, 意味着前26位是网络位.

* 子网掩码是255.255.255.192(26个1, 后面跟6个0, 二进制是11111111.11111111.11111111.11000000).

* 主机位有32-26=6位, 所以这个网络可以有 2^6 - 2 = 62个可用主机地址.

你看, 同样是192.168.1.0这个起点, 通过改变前缀长度(/24 vs /26), 我们划分出了大小不同的网络. 这就是"无类别"和"可变长"的威力.

==== 二进制是理解的基础

一切网络问题, 回到二进制都能看得清清楚楚.

我们以 `192.168.1.0/26` 为例:

. **IP地址:** 192.168.1.0 -> 11000000.10101000.00000001.00**000000**

. **子网掩码:** /26 -> 11111111.11111111.11111111.11**000000**

** 前面26位是1, 标识网络部分.

** 后面6位是0, 标识主机部分.

在这个网络中:

* **网络地址:** 主机位全为0. 11000000.10101000.00000001.00**000000** -> 192.168.1.0

* **广播地址:** 主机位全为1. 11000000.10101000.00000001.00**111111** -> 192.168.1.63

* **可用主机范围:** 192.168.1.1 ~ 192.168.1.62

==== 路由聚合

这是CIDR解决"路由表爆炸"问题的杀手锏.

**场景:** 一个ISP(互联网服务提供商)拥有以下四个连续的C类地址块:

* `192.168.0.0 / 24`

* `192.168.1.0 / 24`

* `192.168.2.0 / 24`

* `192.168.3.0 / 24`

在没有CIDR的情况下, 互联网核心路由器需要为这4个网络维护4条独立的路由条目.

**使用CIDR聚合:**

我们把这四个地址块写成二进制, 看它们的前面多少位是相同的:

* 192.168.0.0 -> 11000000.10101000.000000**00**.00000000

* 192.168.1.0 -> 11000000.10101000.000000**01**.00000000

* 192.168.2.0 -> 11000000.10101000.000000**10**.00000000

* 192.168.3.0 -> 11000000.10101000.000000**11**.00000000

可以看到, 前 **22** 位(11000000.10101000.000000)是完全相同的. 最后两位是变化的.

因此, ISP可以对外只宣告一条聚合路由: `192.168.0.0 / 22`

这条路由就覆盖了从 `192.168.0.0` 到 `192.168.3.255` 的所有地址. 互联网核心路由器只需要记住这一条路由, 大大减少了路由表的规模.

=== CIDR的优势总结

* **高效利用IP地址:** 可以根据实际需要分配合适大小的网络, 避免了A、B、C类地址的浪费.

* **减少路由表大小:** 通过路由聚合, 将多个小网络合并成一个大网络进行通告, 极大地缓解了互联网核心路由器的压力.

* **增强灵活性:** 网络划分不再受固定类别的限制, 网络管理员可以更精细地规划内部网络.

**注意:** **CIDR** 和 **VLSM(可变长子网掩码)** 经常一起被提及. 简单理解, **VLSM是用于网络内部进一步划分子网的技术, 而CIDR是用于网络之间路由聚合的技术**. 两者都基于"无类别"和"可变长子网掩码"这一相同原理.
