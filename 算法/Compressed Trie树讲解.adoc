== Compressed Trie树讲解

压缩 Trie 树(Compressed Trie), 也称为基数树(Radix Tree)或 Patricia 树(Patricia Trie).

=== 为什么需要压缩 Trie? —— 从标准 Trie 的问题说起
首先, 回忆一下**标准 Trie 树**的结构:

* 每个节点存储一个字符.

* 从根节点到某个标记为「终点」的节点的路径, 构成一个字符串.

* 对于每个节点, 可能有多个子节点, 每个子节点对应下一个可能的字符.

**标准 Trie 的问题:**

想象一下存储 **["an", "and", "ant", "bee", "ben"]** 这些单词.
标准 Trie 会为每个字符创建一个节点. 比如 **"and"** 和 **"ant"** 共享了前两个字符 **'a'** 和 **'n'**, 但从 **'n'** 节点开始, 它们分叉成了 **'d'** 和 **'t'**.

这种结构的主要缺点是**空间浪费**. 如果存在很多长字符串且公共前缀很少, 会产生大量只有一个子节点的节点. 这些「单支」节点除了增加深度外, 没有提供任何有用的分叉信息.

=== 什么是压缩 Trie?
压缩 Trie 的核心思想就是**压缩这些「单支」路径**.

**压缩规则:**
将连续的单支节点合并成一个节点, 这个新节点存储的是整个连续的**字符串片段(String Fragment)**, 而不再是单个字符.

经过压缩, Trie 树的高度会显著降低, 节点数量大大减少, 从而节省了空间. 这是一种典型的「以时间换空间」的策略, 虽然节点本身变复杂了(需要存储字符串而不仅是字符), 但整体结构更紧凑.

=== 压缩 Trie 的节点结构
一个压缩 Trie 的节点通常包含以下信息:

. **存储的字符串(label/fragment):** 该节点所代表的字符串片段. 例如, 可能是 **"an"**, **"d"**, **"t"**.

. **子节点指针列表(children):** 指向下一个节点的指针.

. **终止标记(isEndOfWord):** 一个布尔值, 标记从根节点到该节点的路径是否构成了一个完整的键(如一个完整的单词).

=== 构建过程示例
让我们用之前的例子 **["an", "and", "ant", "bee", "ben"]** 来演示如何构建一个压缩 Trie.

**步骤 1: 插入 "an"**

* 树是空的, 直接创建一个根节点, 其标签为 **"an"**, 并标记为终止.

[source, plaintext. linenums]
----
根节点
[label: "an", isEnd: True, children: []]
----

**步骤 2: 插入 "and"**

* 将新键 **"and"** 与根节点的标签 **"an"** 进行比较.

* 发现 **"and"** 的前两个字符 **"an"** 与根节点标签**完全匹配**.

* 现在有剩余字符串 **"d"**.

* 根节点目前没有子节点, 所以直接为剩余部分 **"d"** 创建一个新的子节点, 并标记为终止.

[source, plaintext. linenums]
----
根节点
[label: "an", isEnd: True, children: [ -> 节点A ]]
                              |
                              v
                        节点A [label: "d", isEnd: True, children: []]
----

**步骤 3: 插入 "ant"**

* 比较 **"ant"** 和根节点标签 **"an"**, 匹配.

* 剩余字符串是 **"t"**.

* 现在根节点有一个子节点, 其标签是 **"d"**. 将剩余字符串 **"t"** 与这个子节点的标签 **"d"** 比较.

* 它们没有公共前缀! 这意味着需要在这个节点进行**分裂**.

** 创建一个新的中间节点, 其标签为这两个字符串的**公共前缀**. **"d"** 和 **"t"** 的公共前缀是 ""(空字符串).

** 这实际上意味着当前节点(标签 **"d"**)需要被提升, 并与新键 **"t"** 成为兄弟节点.

* **操作:**

. 创建一个新的子节点(替换原来的 **节点A**), 其标签为空 **""**. 这个节点本身不是单词的终点.

. 将原来的 **节点A("d")**变成这个新节点的子节点.

. 再为 **"t"** 创建一个新的子节点, 挂在这个新节点下.

[source, plaintext. linenums]
----
根节点
[label: "an", isEnd: True, children: [ -> 节点B ]]
                              |
                              v
                节点B [label: "", isEnd: False, children: [ -> 节点A, -> 节点C ]]
                                     |                  |
                                     |                  |
                                     v                  v
节点A [label: "d", isEnd: True, children: []]   节点C [label: "t", isEnd: True, children: []]
----

**步骤 4: 插入 "bee"**

* 比较 **"bee"** 和根节点标签 **"an"**. 没有公共前缀!

* 需要在根节点进行分裂.

** 根节点和 **"bee"** 的公共前缀是 **""**.

* **操作:**

. 创建一个新的根节点, 标签为 **""**.

. 将原来的根节点(**"an"**)变成新根的一个子节点.

. 为 **"bee"** 创建另一个子节点, 挂在新根下.

[source, plaintext. linenums]
----
                        新根节点
             [label: "", isEnd: False, children: [ -> 老根节点, -> 节点D ]]
                           |                          |
                           |                          |
                           v                          v
老根节点 [label: "an", isEnd: True, children: [ -> 节点B ]]   节点D [label: "bee", isEnd: True, children: []]
                           |
                           v
             节点B [label: "", isEnd: False, children: [ -> 节点A, -> 节点C ]]
                           |                  |
                           |                  |
                           v                  v
      节点A [label: "d", isEnd: True, children: []]   节点C [label: "t", isEnd: True, children: []]
----

**步骤 5: 插入 "ben"**

* 比较 **"ben"** 和新根节点的子节点:

** 与 **老根节点(an)**: 不匹配.

** 与 **节点D(bee)**: 比较 **"ben"** 和 **"bee"**.

*** 公共前缀是 **"be"**.

*** 节点D 的剩余后缀是 **"e"**.

*** 新键 **"ben"** 的剩余后缀是 **"n"**.

* **操作:**

. 分裂 **节点D**. 创建一个新的中间节点, 标签为公共前缀 **"be"**.

. 将原来的 **节点D("bee")** 修改: 标签变为剩余部分 **"e"**, 并保持为终止状态.

. 为新键的剩余部分 **"n"** 创建一个新的子节点, 挂在这个新的 **"be"** 节点下, 并标记为终止.

[source, plaintext. linenums]
----
                        新根节点
             [label: "", isEnd: False, children: [ -> 老根节点, -> 节点E ]]
                           |                          |
                           |                          |
                           v                          v
老根节点 [label: "an", ...]                节点E [label: "be", isEnd: False, children: [ -> 节点F, -> 节点G ]]
                                                           |                  |
                                                           |                  |
                                                           v                  v
                                     节点F [label: "e", isEnd: True, children: []]   节点G [label: "n", isEnd: True, children: []]
----

最终, 我们得到了一个非常紧凑的压缩 Trie 结构.

=== 压缩 Trie 的优缺点
优点::

* **空间效率高:** 显著减少了节点数量, 避免了单支节点造成的空间浪费.

* **查询效率可能更高:** 虽然每个节点的比较更复杂(需要比较小字符串), 但由于树高大大降低, 需要访问的节点数更少, 整体查询速度通常优于标准 Trie, 尤其对于长字符串.

缺点::

* **实现复杂:** 插入和删除操作涉及节点的分裂与合并, 逻辑比标准 Trie 复杂得多.

* **节点结构更重:** 每个节点需要存储一个字符串而不仅是一个字符.

=== 应用场景
压缩 Trie 非常适合需要高效存储和查询大量具有公共前缀字符串的场景:

* **字典实现:** 大多数现代编程语言的标准库字典(或对象)实现底层并不直接使用它, 但它是概念基础.

* **路由器中的IP路由表:** IP地址是分层且有公共前缀的, 压缩Trie(Radix Tree)可以高效地进行最长前缀匹配(Longest Prefix Match).

* **文本自动补全(Auto-completion):** 搜索框的提示功能.

* **拼写检查器**

* **基因组学:** 用于存储和搜索DNA序列(由ACGT组成的长字符串).
