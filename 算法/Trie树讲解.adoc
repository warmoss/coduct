== Trie树讲解

Trie 树(发音同 "try"), 又称**前缀树**或**字典树**, 是一种专门用于快速检索字符串数据集中的键的树形数据结构. 这一数据结构在自动补全、拼写检查、搜索引擎、IP路由等多个领域有广泛应用.

=== 核心思想
Trie 树的核心思想是**空间换时间**. 它利用字符串的**公共前缀**来减少不必要的字符串比较, 从而提高查询效率.

* **根节点:** 不包含任何字符信息, 代表空字符串.

* **每个节点:** 代表一个**字符**.

* **从根到某一节点的路径:** 构成一个**字符串前缀**.

* **标记节点:** 在某些节点上做一个标记(例如 **isEnd**), 表示从根节点到该节点的路径构成了一个完整的字符串.

=== 基本结构
我们用一个简单的例子来理解 Trie 树的结构. 假设我们要存储以下单词: **"a"**, **"abc"**, **"add"**, **"abcd"**, **"b"**.

构建出的 Trie 树如下图所示(为清晰起见, 通常不会画出空根节点与字符的对应关系, 而是直接画出子节点):

[source, plaintext, linenums]
----
        (根 Root)
       /         \
      a(isEnd)    b(isEnd)
     /  \
    b    d   ...
   /      \
  c(isEnd) d(isEnd)
 /
d(isEnd)    
----

**解释:**

* 根节点有两个子节点 a 和 b.

* 从根节点经过 a 再到 b, 路径 "ab" 是一个前缀.

* 节点 c 和 d 被标记为 isEnd, 表示 "abc" 和 "add" 是完整的单词.

* 节点 c 下面还有一个 d 也被标记, 表示 "abcd" 也是一个完整的单词.

* 直接连接根节点的 b 节点本身就被标记, 表示 "b" 是一个完整的单词.

=== 主要操作
==== 插入(Insert)
向 Trie 树中插入一个单词 **word**.

. 从根节点开始.

. 遍历 **word** 中的每一个字符 **ch**:

** 如果当前节点的子节点中不存在 **ch**, 则为当前节点创建一个新的子节点 **ch**.

** 将当前节点指向 **ch** 对应的子节点.

. 遍历完所有字符后, 在最后一个节点上标记 **isEnd = true**, 表示这是一个单词的结束.

**示例:** 插入 "add"

. 根节点有子节点 **a**, 存在, 指向 **a** 节点.

. **a** 节点有子节点 **b**, 但没有 **d**. 创建新的子节点 **d**, 并指向它.

. 新的 **d** 节点没有子节点. 创建另一个新的子节点 **d**, 并指向它.

. 在第二个 **d** 节点上标记 **isEnd = true**.

==== 搜索(Search)
在 Trie 树中搜索一个完整的单词 **word**.

. 从根节点开始.

. 遍历 **word** 中的每一个字符 **ch**:

** 如果当前节点的子节点中不存在 **ch**, 返回 **false**(未找到).

** 否则, 将当前节点指向 **ch** 对应的子节点.

. 遍历完所有字符后, 检查当前节点的 **isEnd** 是否为 **true**.

** 如果为 **true**, 返回 **true**(找到了完整单词).

** 如果为 **false**, 说明 **word** 只是某个词的前缀, 而不是一个完整的单词, 返回 **false**.

**示例:** 搜索 **"ab"** 和 **"abc"**

搜索 **"ab"**: 能顺利走到 **b** 节点, 但该节点的 **isEnd** 是 **false**(在我们的例子中), 所以返回 **false**.

搜索 **"abc"**: 能顺利走到 **c** 节点, 且该节点的 **isEnd** 是 **true**, 所以返回 **true**.

==== 前缀搜索(StartsWith)
检查 Trie 树中是否有以前缀 **prefix** 开头的单词.

这个操作与 **搜索** 几乎完全相同, 唯一的区别是: **不需要检查最后一个节点的 isEnd 标记**. 只要能够遍历完 **prefix** 的所有字符, 就说明存在以该前缀开头的单词.

**示例:** 检查 **"ab"** 是否存在

能顺利走到 **b** 节点, 即使 **isEnd** 是 **false**, 也返回 **true**, 因为存在 **"abc"**, **"abd"** 等以 **"ab"** 开头的单词.

=== 代码实现(Python 示例)
下面是一个简单的基于字典(HashMap)的 Trie 节点实现.

[source, python, linenums]
----
class TrieNode:
    def __init__(self):
        self.children = {}  # 映射: 字符 -> TrieNode
        self.is_end = False # 标记是否是单词结尾

class Trie:
    def __init__(self):
        self.root = TrieNode() # 根节点

    def insert(self, word: str) -> None:
        node = self.root
        for char in word:
            # 如果字符不在子节点中, 则创建一个新节点
            if char not in node.children:
                node.children[char] = TrieNode()
            node = node.children[char] # 移动到下一个节点
        node.is_end = True # 标记单词结束

    def search(self, word: str) -> bool:
        node = self.root
        for char in word:
            if char not in node.children:
                return False
            node = node.children[char]
        return node.is_end # 关键: 必须是一个完整的单词

    def startsWith(self, prefix: str) -> bool:
        node = self.root
        for char in prefix:
            if char not in node.children:
                return False
            node = node.children[char]
        return True # 关键: 不需要检查 is_end, 只要前缀存在即可
----

=== 优缺点分析
优点::

. **查询高效:** 查询一个单词或前缀的时间复杂度为 O(L), 其中 L 是单词的长度. 这与字典中单词的数量无关, 效率非常高.

. **前缀查询:** 非常适合做前缀匹配和自动补全功能, 这是哈希表等数据结构不擅长的.

缺点::

. **空间消耗大:** 每个节点都需要存储子节点的指针(或引用). 如果字符集很大(如包含所有 Unicode 字符), 而存储的单词公共前缀不多, 会浪费大量内存.

. **内存不连续:** 基于指针的结构, 对缓存不友好.

**优化:** 可以使用 **压缩字典树(Compressed Trie)** 来减少节点数, 节省空间, 但会增加实现的复杂性.

=== 应用场景
* **搜索引擎自动补全:** 输入几个字符, 快速提示可能的关键词.

* **拼写检查:** 快速判断一个单词是否在字典中.

* **IP 路由最长前缀匹配:** 在路由器中, 根据IP地址的前缀查找最优的下一跳地址.

* **输入法预测:** 根据输入的音节或笔画预测可能的词语.

* **单词游戏:** 如 Scrabble, Boggle 等, 快速判断字母组合是否构成有效单词.

=== 总结
Trie 树是一种非常强大且直观的专门用于处理字符串的数据结构. 它的优势在于利用前缀共享来加速查询, 尤其适合做前缀相关的搜索和匹配. 虽然它有一定的空间开销, 但在很多对查询速度要求高的场景下, 它是无可替代的最佳选择.
