== KMP算法讲解

KMP 算法(Knuth-Morris-Pratt)是一种高效的**字符串匹配算法**, 由 Donald Knuth、James H. Morris 和 Vaughan Pratt 三位计算机科学家共同提出. 它解决了在一个**主串**(text)中查找一个**模式串**(pattern)所有出现位置的问题, 核心优势在于利用已匹配部分的信息避免回溯, 将时间复杂度从朴素的 O(n*m) 降低到 O(n+m).

=== 问题定义

字符串匹配问题:: 给定一个**主串** T(长度 n)和一个**模式串** P(长度 m), 找出 P 在 T 中的所有出现位置.

朴素算法的做法是: 从 T 的每个位置开始, 逐字符与 P 比较. 当发生失配时, 模式串只右移一位, 重新从模式串开头比较, 导致大量重复比较.

[source, python]
----
def brute_force(text: str, pattern: str) -> int:
    """
    朴素字符串匹配算法
    :param text: 主串
    :param pattern: 模式串
    :return: 模式串在主串中第一次出现的位置，若未找到则返回 -1
    """
    n, m = len(text), len(pattern)
    for i in range(n - m + 1):
        j = 0
        while j < m and text[i + j] == pattern[j]:
            j += 1
        if j == m:
            return i
    return -1
----

KMP 的核心理念是: **当失配发生时, 模式串中已经匹配的部分蕴含了足够的信息, 来决定模式串应该向右移动多少位, 而不需要回退主串指针**.

=== 核心概念: 前缀函数(Partial Match Table)

前缀函数(又称 **next 数组** 或 **失配函数**)是 KMP 算法的灵魂. 它为模式串 P 的每个位置 i 计算一个值 stem:[ \pi[i] ], 定义如下:

前缀函数 stem:[\pi[i]]:: 对于位置 i(0-based), stem:[\pi\[i\]] 表示子串 P[0..i] 中, **最长的相等真前缀和真后缀的长度**.

说明几个关键点:

* **真前缀**: 不包含整个字符串的前缀. 对于 "abc", 真前缀是 ""(空串), "a", "ab".

* **真后缀**: 不包含整个字符串的后缀. 对于 "abc", 真后缀是 ""(空串), "c", "bc".

* stem:[\pi[i\]] 表示这个最长公共前后缀的长度.

* stem:[\pi[0\] = 0] (长度为 1 的子串没有真前后缀).

==== 计算示例

以模式串 P = "ababaca" 为例, 计算其前缀函数:

[cols="3*"]
|===
| i | P[0..i] | stem:[\pi[i\]]

| 0 | a | 0
| 1 | ab | 0
| 2 | aba | 1 ("a" == "a")
| 3 | abab | 2 ("ab" == "ab")
| 4 | ababa | 3 ("aba" == "aba")
| 5 | ababac | 0
| 6 | ababaca | 1 ("a" == "a")
|===

得到 `next` 数组 = [0, 0, 1, 2, 3, 0, 1].

=== 前缀函数的计算

计算前缀函数的核心思想是**递推**. 已知 stem:[\pi[0..i-1\]], 求 stem:[\pi[i\]]:

. 令 `j = π[i-1]`, 即前一个位置的最长公共前后缀长度.

. 比较 P[i] 与 P[j]:

** 如果 P[i] == P[j], 则 stem:[\pi[i\] = j + 1].

** 否则, 令 `j = π[j-1]`(回退到更短的前缀), 重复步骤 2, 直到 j == 0 或找到匹配.

. 如果 j == 0 且 P[i] != P[0], 则 stem:[\pi[i\] = 0].

[source, python]
----
def compute_prefix_function(pattern: str) -> list[int]:
    m = len(pattern)
    pi = [0] * m
    for i in range(1, m):
        j = pi[i - 1]
        # 当不匹配且 j > 0 时, 回退到更短的前缀
        while j > 0 and pattern[i] != pattern[j]:
            j = pi[j - 1]
        # 如果匹配, 长度加 1
        if pattern[i] == pattern[j]:
            j += 1
        pi[i] = j
    return pi
----

=== 匹配过程

有了前缀函数后, 匹配过程与计算前缀函数高度相似:

. 使用两个指针: **i** 遍历主串 T, **j** 指向模式串 P 的当前匹配位置.

. 比较 T[i] 与 P[j]:

** 如果相等, i++, j++(匹配成功). 如果 j == m, 说明找到一个完整匹配, 记录位置, 然后令 j = stem:[\pi[j-1\]] 继续搜索.

** 如果不等且 j > 0, 利用前缀函数回退: j = stem:[\pi[j-1\]], 主串指针 i 不回退.

** 如果不等且 j == 0, i++(主串指针向前移动).

[source, python]
----
def kmp_search(text: str, pattern: str) -> list[int]:
    pi = compute_prefix_function(pattern)
    matches = []
    j = 0  # 模式串指针
    
    for i in range(len(text)):
        # 失配时通过前缀函数回退, 主串指针不回退
        while j > 0 and text[i] != pattern[j]:
            j = pi[j - 1]
        
        if text[i] == pattern[j]:
            j += 1
        
        if j == len(pattern):
            matches.append(i - j + 1)  # 匹配起始位置
            j = pi[j - 1]  # 继续查找下一个匹配
    
    return matches
----

=== 完整示例

以主串 T = "abababacaba", 模式串 P = "ababaca" 为例, 模拟匹配过程:

. i=0..4 匹配 "ababa", j=0..4, 此时 j=5, i=4.

. i=5(T[5]=b), P[5]=c, 失配. j = stem:[\pi[4\]] = 3.

. T[5]=b, P[3]=b, 匹配, j=4, i=6.

. i=6(T[6]=a), P[4]=a, 匹配, j=5, i=7.

. i=7(T[7]=c), P[5]=c, 匹配, j=6, i=8.

. i=8(T[8]=a), P[6]=a, 匹配, j=7=m, **找到匹配**, 位置 i-j+1=2. 回退 j = stem:[\pi[6\]] = 1.

. 继续匹配直至结束.

[source, text]
----
== 失配回退 ==
T: a b a b a b a c a b a
P: a b a b a c a
             ^ 失配于 j=5
P(回退后):     a b a b a c a
             j=3, P[3]=b, T[5]=b -> 匹配

== 继续匹配 ==
T: a b a b a b a c a b a
P:         a b a b a c a
                    ^
            匹配成功于位置 2
----

=== 时间复杂度分析

* **前缀函数计算:** 循环中 i 迭代 m-1 次, j 的每次回退都对应一次 j 的减少(而 j 最多增加 m-1 次), 总复杂度 **O(m)**.

* **匹配过程:** 主串指针 i 迭代 n 次, 不回退; j 的回退次数与增加次数同量级, 总复杂度 **O(n)**.

* **总体复杂度: O(n+m)**, 其中 n 为主串长度, m 为模式串长度.

这是**线性时间**的字符串匹配算法, 相比朴素算法的 O(n*m) 有质的飞跃.

=== 优缺点分析

优点::

. **线性时间复杂度:** O(n+m), 无论什么输入都能保证.
. **不需要回溯主串指针:** 特别适合处理流式数据或只读输入.
. **理论优雅:** 前缀函数的设计体现了"利用过去信息指导未来"的计算思维.

缺点::

. **实现相对复杂:** 前缀函数的理解和实现比朴素算法和 Boyer-Moore 算法复杂.
. **常数较大:** 实际应用中, 对于较短的模式串或普通文本, Boyer-Moore 或标准库的优化实现可能更快.
. **不适用于多模式匹配:** 需要同时匹配多个模式串时应使用 Aho-Corasick 算法(参见 <<Aho-Corasick算法讲解>>).

=== 与相关算法的对比

[cols="4*"]
|===
| 算法 | 时间复杂度(一般) | 时间复杂度(最坏) | 特点

| 朴素匹配 | O(n*m) | O(n*m) | 简单直观, 无预处理
| KMP | O(n+m) | O(n+m) | 线性时间, 不回退主串指针
| Boyer-Moore | O(n/m)~O(n+m) | O(n*m) | 实际最快, 从右向左匹配

| Aho-Corasick | O(n+m+z) | O(n+m+z) | 多模式匹配, 基于 Trie
|===

=== 总结

KMP 算法是字符串匹配领域的奠基性算法, 其核心贡献在于提出了**前缀函数**的概念, 通过预处理模式串的自相似性信息, 实现了失配时的高效跳转, 避免了主串指针的回退.

理解 KMP 的关键在于理解前缀函数的递推计算过程: **每一次 j 的回退并不是盲目的, 而是利用了已计算的 stem:[\pi[j-1\]] 信息, 跳到下一个可能匹配的前缀位置**. 这一思路在计算前缀函数和匹配过程中是完全一致的, 因此代码结构也非常相似.

KMP 的思想影响力远超字符串匹配本身, 在压缩算法、DNA 序列分析、自然语言处理等领域都有广泛应用.
