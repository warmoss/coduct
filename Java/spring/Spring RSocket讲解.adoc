== Spring RSocket讲解

RSocket 本身是一个 *应用层* 的、支持 *响应式流* 的二进制通信协议. 而 Spring RSocket 则是 Spring 生态对 RSocket 协议的全面整合, 让你能够以熟悉的 Spring 风格(如使用注解 *@Controller*)来构建高性能、双向通信的分布式应用.

=== 为什么需要 RSocket? 解决了什么问题?
在微服务和分布式系统中, 传统的 HTTP 请求/响应模式(如 REST)在一些场景下显得力不从心:

. *单向通信:* HTTP 是严格的“一问一答”, 服务器无法主动向客户端推送消息.

. *通信开销:* 每个请求都需要建立 TCP 连接(虽然 HTTP/2 解决了多路复用, 但本质未变).

. *弱实时性:* 对于需要持续数据流的场景(如股票报价、日志流), HTTP 通常靠轮询或 SSE, 效率低下.

. *复杂的错误处理:* HTTP 错误码有时不足以表达复杂的业务错误信息.

RSocket 被设计用来解决这些问题, 它提供了四种灵活的交互模型, 并且是 *基于连接* 的, 在单个长连接上实现多路复用.

=== RSocket 的四种核心交互模型
这是理解 RSocket 的关键:

. *Request-Response (requestResponse)*

* *模式:* 最熟悉的模式. 客户端发送一个请求, 期望从服务器得到一个响应.

* *类比:* 类似于 HTTP GET/POST 请求.

* *应用场景:* 查询用户信息、提交订单等.

. *Request-Stream (requestStream)*

* *模式:* 客户端发送一个请求, 期望从服务器得到一个 *数据流*(多个响应).

* *类比:* 类似于 Server-Sent Events (SSE).

* *应用场景:* 获取实时股票价格、接收日志流、监控数据等.

. *Fire-and-Forget (fireAndForget)*

* *模式:* 客户端发送一个请求, 但 *不期望* 从服务器得到任何响应.

* *类比:* 类似于发送一个 UDP 包, 但基于可靠的连接.

* *应用场景:* 非关键事件的日志记录、传感器数据上报(如温度读数).

. **Channel (channel)**

* *模式:* 最强大的模式. 客户端和服务器之间建立 *双向的*、*全双工* 的数据流通道.

* *类比:* 类似于 WebSocket, 但更强大, 支持背压.

* *应用场景:* 实时聊天室、多人游戏同步、双向数据管道.

*核心优势:* 所有交互模型都天然支持**响应式流背压(Backpressure)**, 消费者可以控制生产者的速度, 防止被淹没, 这是 RSocket 相比许多其他协议的一大亮点.

=== Spring 如何集成 RSocket
Spring RSocket 将 RSocket 的服务端和客户端都变成了 Spring Bean, 你可以通过熟悉的注解来定义和处理通信.

==== 服务端-依赖导入 (Maven)

[source, xml, linenums]
----
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-rsocket</artifactId>
</dependency>
----

==== 服务端-配置传输层
在 application.yml 中配置, 例如使用 TCP:
[source, yaml, linenums]
----
spring:
  rsocket:
    server:
      port: 7000
      transport: tcp
----

==== 服务端-编写处理器 (Handler / Controller)
使用 **@Controller** 注解, 并定义处理各种交互模型的方法.

[source, java, linenums]
----
@Controller
public class MarketDataController {

    // 1. Request-Response
    @MessageMapping("current market data")
    public MarketData getCurrentMarketData(MarketDataRequest request) {
        return service.getCurrentData(request);
    }

    // 2. Request-Stream
    @MessageMapping("market data stream")
    public Flux<MarketData> getMarketDataStream(MarketDataRequest request) {
        return service.getDataStream(request); // 返回一个Flux, 即数据流
    }

    // 3. Fire-and-Forget
    @MessageMapping("alert")
    public void setAlert(MarketDataAlert alert) {
        service.handleAlert(alert); // 方法返回void
    }

    // 4. Channel (双向流)
    @MessageMapping("market data channel")
    public Flux<MarketData> marketDataChannel(Flux<MarketDataRequest> requests) {
        // 入参是Flux, 代表来自客户的请求流
        // 出参是Flux, 代表发往客户的响应流
        return requests
                .switchMap(service::getDataStream);
    }
}
----

**@MessageMapping:** 类似于 Spring MVC 的 **@RequestMapping**, 定义了路由标识符.

==== 客户端-创建和配置 RSocket 客户端 Bean

[source, java, linenums]
----
@Configuration
public class ClientConfiguration {

    @Bean
    public RSocketRequester rSocketRequester(RSocketStrategies strategies) {
        return RSocketRequester.builder()
                .rsocketStrategies(strategies)
                // 配置TCP连接器, 连接到本地7000端口
                .tcp("localhost", 7000);
    }
}
----

==== 在服务中调用远程方法

[source, java, linenums]
----
@Service
public class TradingService {

    @Autowired
    private RSocketRequester rSocketRequester;

    // 1. 调用 Request-Response
    public Mono<MarketData> getCurrentPrice(String stockSymbol) {
        return rSocketRequester
                .route("current market data")
                .data(new MarketDataRequest(stockSymbol))
                .retrieveMono(MarketData.class);
    }

    // 2. 调用 Request-Stream
    public Flux<MarketData> getPriceStream(String stockSymbol) {
        return rSocketRequester
                .route("market data stream")
                .data(new MarketDataRequest(stockSymbol))
                .retrieveFlux(MarketData.class);
    }

    // 3. 调用 Fire-and-Forget
    public void sendAlert(MarketDataAlert alert) {
        rSocketRequester
                .route("alert")
                .data(alert)
                .send() // 使用send()而不是retrieveXxx()
                .subscribe();
    }
}
----

* **route():** 指定服务端 **@MessageMapping** 的路由.
* **data():** 设置请求负载(数据).
* **retrieveMono() / retrieveFlux():** 声明期望的响应类型.
* **send():** 用于 Fire-and-Forget, 只发送不接收.

=== 高级特性
* **负载均衡与服务发现:** Spring Cloud RSocket 可以与 Spring Cloud LoadBalancer 集成, 实现客户端的负载均衡. **RSocketRequester** 可以连接到 **spring-cloud-starter-rsocket** 发现的服务名, 而不是具体的 IP 和端口.

* **安全:** 支持基于 Spring Security 的认证和授权, 例如 JWT.

* **连接恢复:** RSocket 支持会话恢复, 在网络中断重连后可以恢复之前的连接状态.

* **编码解码:** 通过 **RSocketStrategies** 高度可配置, 支持 JSON、Protobuf 等多种序列化方式.

=== 与 WebFlux/WebSocket 的对比

[cols="1,2,2,2"]
|===
|特性|Spring RSocket|WebFlux (HTTP)|WebSocket

|**协议**
|二进制应用层协议
|HTTP/1.1, HTTP/2
|WebSocket (基于 HTTP)

|**交互模型**
|4 种 (Req-Res, Stream, etc.)
|主要 Request-Response
|双向消息（但无标准模式）

|**背压**
|**原生支持**
|在 Stream 上支持
|需要自行实现

|**多路复用**
|**原生支持**
|HTTP/2 支持
|是

|**连接**
|单条长连接
|通常短连接 (HTTP/1.1)
|通常短连接 (HTTP/1.1)

|**编程模型**
|响应式 (Reactive)
|响应式 (Reactive)
|事件驱动或响应式

|===

**简单总结:** 如果你需要构建一个**全栈响应式**、并且需要**多种交互模式**(尤其是服务器推送和双向流)的低延迟、高效率应用, **Spring RSocket 是一个极佳的选择**. 如果只是简单的请求-响应或浏览器兼容性是首要考虑, 那么 HTTP (WebFlux) 和 WebSocket 仍然是更安全普遍的选择.
