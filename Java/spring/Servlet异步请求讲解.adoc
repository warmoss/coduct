== Servlet异步请求讲解

=== 为什么需要异步Servlet(同步模型的瓶颈)
在传统的 *同步Servlet模型* 中, 整个请求-响应周期的工作流程是这样的:

. *请求到来*: Web 容器(如 Tomcat)从它的线程池(HTTP 线程池)中分配一个线程(我们叫它 HTTP 线程)来处理请求.

. *执行业务逻辑*: 在你的 *service*, *doGet*, 或 *doPost* 方法中, 所有的代码(包括数据库查询、调用外部 API、复杂的计算等)都在这个 HTTP 线程上执行.

. *生成响应*: 业务逻辑执行完毕后, *将结果*返回给客户端.

. *线程释放*: HTTP 线程被释放, 回到容器线程池, 准备处理下一个请求.

*瓶颈所在:* 如果某个业务操作非常耗时(例如, 一个需要等待 3 秒的数据库查询或远程服务调用), 那么处理这个请求的 *HTTP 线程就会被一直占用着*. 在这 3 秒内, 这个线程什么也做不了, 只是等待. 如果同时有大量这样的耗时请求, *容器的所有 HTTP 线程都可能被耗尽*, 导致新的请求无法被处理, 即使服务器 CPU 很空闲. 这就是同步模型的扩展性问题.

=== 异步 Servlet 的核心思想
异步 Servlet 的核心思想是: *将耗时的业务操作委派给另一个单独的线程去执行, 从而立即释放宝贵的 HTTP 线程, 让它回去处理新的请求.*

它的工作流程如下:

. *请求到来*: HTTP 线程开始处理请求.

. *开启异步上下文*: 在 Servlet 中, 你通过调用 *request.startAsync()* 开启异步模式, 并获得一个 *AsyncContext* 对象. *关键一步: 这之后, HTTP 线程与请求的关联被解除.*

. *释放 HTTP 线程*: HTTP 线程立即返回容器线程池, 可以继续去处理其他新的请求. *此时, 对客户端的响应尚未生成.*

. *委派耗时任务*: 你将 *AsyncContext* 对象传递给一个专门用于处理耗时任务的业务线程池(不是你容器的 HTTP 线程池).

. *异步处理*: 业务线程池中的某个线程接手这个任务, 开始执行漫长的操作(如数据库查询).

. *完成与响应*: 耗时任务完成后, 业务线程使用 *AsyncContext* 对象获取到请求和响应对象, 并生成结果发送给客户端.

. *结束请求*: 调用 *asyncContext.complete()* 来最终结束这个请求.
