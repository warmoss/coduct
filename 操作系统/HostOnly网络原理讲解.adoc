== HostOnly网络原理讲解

Host-Only 网络, 中文称"仅主机网络", 是 VirtualBox, VMware 等虚拟化平台提供的一种虚拟网络模式. 它把虚拟机和宿主机接入同一个与外部物理网络完全隔离的私有网段, 使虚拟机之间、虚拟机与宿主机之间可以互相通信, 但虚拟机无法直接访问互联网. 理解 Host-Only 网络, 是掌握虚拟机网络隔离和网络安全实验的基础.

=== 什么是 Host-Only 网络

Host-Only 网络:: 虚拟化平台在宿主机上创建的, 只包含宿主机和虚拟机的封闭二层网络. 它通过一个软件实现的虚拟交换机和一张宿主机侧虚拟网卡, 把若干虚拟机连成私有网段, 不提供任何通往外部网络的上行链路.

* **私有性:** 网段内的流量只在宿主机内存中流转, 不会进入物理网络.
* **双向受限:** 虚拟机无法访问外网, 外网也无法访问虚拟机.
* **宿主机参与:** 宿主机通过一张虚拟网卡加入该网段, 可以与虚拟机通信.

=== 为什么需要 Host-Only 网络

在需要"既能管理虚拟机, 又不让虚拟机接触外网"的场景下, NAT 模式和桥接模式都无法满足:

* **NAT 模式:** 虚拟机能通过宿主机访问外网, 隔离性不彻底, 恶意流量可能经由 NAT 泄露到外部.
* **桥接模式:** 虚拟机等同于物理网络中的真实主机, 与外网完全互通, 几乎没有隔离.
* **Host-Only 模式:** 虚拟机与外部网络彻底隔离, 但宿主机仍可访问虚拟机, 兼顾了隔离性与可管理性.

=== 核心组成

Host-Only 网络由三类要素构成, 全部由虚拟化软件在宿主机上创建:

[cols="1,3"]
|===
|组成 |作用

|宿主机虚拟网卡
|宿主机侧的一张软件网卡, VMware 称为 `VMnet1`, VirtualBox 称为 `vboxnet0`. 它是宿主机进入该私有网段的"入口".

|虚拟交换机
|软件实现的二层交换机, 将宿主机虚拟网卡与所有使用 Host-Only 模式的虚拟机网卡桥接在一起.

|虚拟机虚拟网卡
|每台使用 Host-Only 模式的虚拟机都持有一张虚拟网卡, 接入同一个虚拟交换机.

|DHCP 服务器
|虚拟化平台内置的 DHCP 服务, 为虚拟机自动分配私有 IP 地址.
|===

=== 工作原理

Host-Only 网络的核心机制是: **用虚拟交换机把虚拟机网卡和宿主机虚拟网卡连成一个封闭的二层广播域, 且不提供任何出网路径**.

[plantuml, "Host-Only 网络拓扑", format=png]
----

}

  [虚拟网卡 eth0\n192.168.56.101] as vma

  [虚拟网卡 eth0\n192.168.56.102] as vmb
}

vmb -- sw

@enduml
----

==== 虚拟机之间的通信

. 虚拟机 A 向虚拟机 B 发送数据包, 目标地址为 192.168.56.102.
. 数据包经 A 的虚拟网卡发出, 进入虚拟交换机.
. 虚拟交换机根据 MAC 地址表查找目标 MAC 对应的端口.
. 若表中有记录, 直接从该端口转发给 B 的虚拟网卡; 若没有记录, 则向所有端口泛洪.
. 整个过程在宿主机内存中完成, 不经过任何物理网卡.

==== 虚拟机与宿主机之间的通信

. 虚拟机 A 向宿主机虚拟网卡地址(如 192.168.56.1)发送数据包.
. 数据包经虚拟交换机转发到宿主机虚拟网卡 `VMnet1`.
. 宿主机虚拟网卡把数据包交给宿主机的内核网络协议栈.
. 宿主机上运行的 SSH, HTTP 等工具即可与虚拟机交互.

==== 为何无法访问外网

. 虚拟机 A 向互联网地址(如 8.8.8.8)发送数据包.
. 虚拟交换机查找目标 MAC 失败, 向所有端口泛洪.
. 但所有端口都只连接着虚拟机网卡和宿主机虚拟网卡, 没有任何上行链路连到物理网卡.
. 同时虚拟化平台也不对该网段执行 NAT 转换.
. 数据包无处可去, 最终被丢弃, 通信失败.

=== DHCP 与地址分配

虚拟化平台内置的 DHCP 服务器负责 Host-Only 网段的地址管理:

* **VMware:** 默认网段为 `192.168.x.0/24`, 宿主机虚拟网卡 `VMnet1` 取 `192.168.x.1`.
* **VirtualBox:** 默认网段为 `192.168.56.0/24`, 宿主机虚拟网卡 `vboxnet0` 取 `192.168.56.1`.
* 虚拟机开机后以广播方式发送 DHCP Discover, 内置 DHCP 服务器分配一个网段内地址.

[source,shell]
----
# 查看宿主机上的 Host-Only 虚拟网卡 (VirtualBox)
ip addr show vboxnet0
# inet 192.168.56.1/24

# 查看宿主机上的 Host-Only 虚拟网卡 (VMware)
ip addr show vmnet1
----

=== 典型应用场景

* **恶意软件分析:** 在隔离网段中运行可疑样本, 防止其对外扩散, 同时宿主机可远程观察.
* **开发测试集群:** 用多台虚拟机搭建 Web 服务器与数据库集群, 组网封闭但宿主机可直接管理.
* **渗透测试靶场:** 在 Host-Only 网段内搭建靶机与攻击机, 攻击流量不会波及物理网络.
* **网络实验教学:** 提供可反复重置的私有网段, 适合演示二层转发, DHCP 等原理.

=== 总结与注意事项

* **Host-Only 网络** 通过宿主机虚拟网卡加虚拟交换机, 构建一个与外界完全隔离的私有网段.
* 虚拟机之间、虚拟机与宿主机之间可以通信, 但虚拟机无法访问互联网, 外网也无法访问虚拟机.
* 与 NAT 模式相比, Host-Only 隔离更彻底; 与内部网络模式相比, 宿主机仍保留管理入口.

WARNING: 需要虚拟机临时访问外网时, 可给虚拟机额外增加一张 NAT 模式网卡, 但要注意这会在一定程度上削弱隔离性.

* 多台物理宿主机上的 Host-Only 网络彼此独立, 默认不互通.
* 若宿主机虚拟网卡地址与物理网络网段冲突, 可能导致宿主机路由异常, 建议使用默认私有网段.
