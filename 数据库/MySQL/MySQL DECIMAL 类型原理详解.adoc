== MySQL DECIMAL 类型原理详解

=== 概述
DECIMAL 是 MySQL 中用于存储精确小数的数据类型, 特别适合财务、货币等需要精确计算的场景.

=== DECIMAL 语法

[source, sql]
----
DECIMAL(M, D)
----

* M: 精度, 总位数(1-65)

* D: 小数位数(0-30, 且 D ≤ M)

* 示例: DECIMAL(10,2) 表示总共10位, 其中小数部分2位

=== 存储原理

==== 存储格式

* **二进制打包格式**: 每个十六进制数字使用4位(半个字节)存储

* **每9位数字打包为4字节**(效率优化)

* 剩余位数单独处理

==== 存储空间计算

[source, text]
----
每9位数字 -> 4字节
剩余位数R -> ceil(R * 4 / 9) 字节
符号位 -> 1位(0正1负)
----

示例计算:

[source, sql]
----
DECIMAL(10,2) 的存储空间:
- 总位数: 10
- 前9位: 4字节
- 剩余1位: ceil(1*4/9) = 1字节
- 总计: 4 + 1 = 5字节
----

==== 实际存储结构

[source, text]
----
[符号位][整数部分][小数部分]
----

* 符号位: 单独1位

* 整数部分: 从高位到低位存储

* 小数部分: 从高位到低位存储

=== 与 FLOAT/DOUBLE 对比

|===
|特性|DECIMAL|FLOAT/DOUBLE
|精度|精确|近似
|存储方式|打包十进制|IEEE 754 二进制
|适用场景|财务计算|科学计算
|比较运算|精确比较|可能误差
|存储空间|固定|固定
|===

=== 内部实现细节

==== 二进制表示

[source, c]
----
// 简化的内部结构(概念性)
struct decimal_t {
    int intg;      // 整数部分位数
    int frac;      // 小数部分位数
    int sign;      // 符号
    byte buf[];    // 数字存储缓冲区
};
----

==== 计算规则

* 加减法: 对齐小数点, 按位计算

* 乘法: 结果小数位数 = 两个操作数小数位数之和

* 除法: 需要指定结果精度或四舍五入

=== 性能考虑

优点::

* **精确计算:** 无舍入误差

* **确定性:** 结果可预测

* **适合财务:** 符合会计要求

缺点::

* **存储空间大:** 相比FLOAT/DOUBLE

* **计算速度慢:** 需要十进制运算

* **内存占用高**

=== 最佳实践

==== 合理选择精度

[source, sql]
----
-- 根据业务需求选择
订单金额: DECIMAL(10, 2)     -- 百万级别, 分单位
汇率: DECIMAL(8, 6)          -- 6位小数足够
科学计算: DECIMAL(20, 10)    -- 高精度需求
----

==== 计算时的注意事项

[source, sql]
----
-- 明确指定精度
SELECT CAST(a * b AS DECIMAL(15, 4)) 
FROM calculations;

-- 避免隐式转换
SELECT decimal_column + 1.0  -- 1.0被视为DECIMAL
FROM table;
----

==== 索引优化

[source, sql]
----
-- DECIMAL列可以创建索引
CREATE INDEX idx_amount ON financial_records(amount);

-- 但注意索引大小, DECIMAL索引比整数索引大
----

=== 实际应用场景

==== 金融系统

[source, sql]
----
-- 账户余额
CREATE TABLE accounts (
    account_id BIGINT,
    balance DECIMAL(15, 2)  -- 支持千亿级别
);

-- 利息计算
UPDATE accounts 
SET balance = balance * (1 + 0.00365)  -- 日利率
WHERE account_id = 1001;
----

==== 电商系统

[source, sql]
----
-- 商品价格
CREATE TABLE products (
    product_id BIGINT,
    price DECIMAL(10, 2),
    discount DECIMAL(3, 2)  -- 0.00-1.00
);
----

=== 总结

DECIMAL类型是MySQL中实现精确小数计算的核心数据类型:

. 使用二进制打包格式存储, 保证精度

. 适合财务、货币等需要精确计算的场景

. 需要权衡精度、存储空间和性能

. 在实际使用中应根据业务需求合理选择精度

选择DECIMAL还是FLOAT/DOUBLE, 关键在于业务是否需要**绝对精确**的计算结果. 对于财务系统, DECIMAL是必须的; 对于科学计算或统计分析, FLOAT/DOUBLE可能更合适.
