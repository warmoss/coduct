== ruff讲解

Python 工程长期被**工具链碎片化**困扰: 语法规范依赖 `pycodestyle`, 未使用导入等错误依赖 `pyflakes`, 加上 `isort`, `pyupgrade`, `flake8-bugbear` 等一堆插件, 再叠加启动慢, 全量扫描耗时的 `flake8`/`pylint`. 每次检查都要拉起多个 Python 进程, 大仓库动辄几十秒. **Ruff** 是 Astral 公司用 Rust 编写的代码检查与格式化工具, 官方基准通常比 `flake8` 快 10-100 倍, 目标是以**单个静态二进制**统一 Python 生态中的 lint, format, import 排序等整条工具链.

=== 概念定义

Ruff:: 用 Rust 编写的 Python **linter(代码检查器)** 与 **formatter(格式化器)**, 兼容 `flake8`/`isort`/`pyupgrade` 的规则体系, 并对齐 `Black` 的格式化风格, 通过单一可执行文件统一提供.

Lint(代码检查):: 静态分析源码, 在不运行程序的前提下发现**潜在 bug**, **风格问题**与**未使用代码**等.

Format(格式化):: 将源码重排为统一的书写风格, 如缩进, 引号, 运算符两侧空格, 是否尾随逗号等, 消除团队间的格式争论.

Rule code(规则编码):: 每条规则以**前缀 + 数字**标识, 前缀对应规则来源, 如 `F401` 中的 `F` 代表 pyflakes, `401` 是规则序号.

Safe fix(安全修复):: Ruff 对每个诊断标注可修复性; 安全修复(`--fix`)不改变程序行为, 不安全修复(`--unsafe-fixes`)可能改变语义, 需人工确认.

`ruff check` 负责发现问题并尽可能自动修复, `ruff format` 负责把代码重排为统一风格, 两者通过不同子命令解耦, 互不干扰.

=== 为什么需要 Ruff

传统工具链存在以下痛点:

* **工具繁多** - lint, format, import 排序, 语法升级各用一套工具, 配置分散且规则互相冲突
* **速度慢** - 每个工具都是独立 Python 进程, 都要各自解析一遍源码, 全量扫描耗时明显
* **依赖重** - 需要在虚拟环境安装多个包, 并持续维护其版本兼容

Ruff 通过**规则重实现**与**单二进制分发**化解这些问题. 下表是它与主流工具的关系:

[cols="1,1,2"]
|===
| 工具 | 职责 | 与 Ruff 的关系
| `flake8` | lint | Ruff 重实现了其默认规则及 pyflakes, pycodestyle, bugbear 等插件规则
| `Black` | format | `ruff format` 提供对齐 Black 稳定风格的格式化
| `isort` | import 排序 | Ruff 内置 `I` 规则组, 检查并修复导入顺序
| `pyupgrade` | 语法现代化 | Ruff 内置 `UP` 规则组, 如把 `%` 格式化改写为 f-string
| `pylint` | 深度检查 | Ruff 实现了 `PL` 规则组中的部分规则
|===

由此, 一个仓库往往只需一个工具即可覆盖原来的整套配置.

==== 速度从何而来

Ruff 之所以快, 核心在于**用 Rust 重写解析与检查, 并复用一次解析结果执行所有规则**:

* **零解释器开销** - 编译为原生二进制直接运行, 无 Python 进程启动与导入开销
* **自研解析器** - 解析结果以 **CST(Concrete Syntax Tree, 具体语法树)** 保存, 完整保留空白与注释, 单次构建即可服务检查, 修复与格式化
* **单遍执行** - 所有启用的规则在同一棵树上运行, 而非像 `flake8` 那样每个插件各解析一次
* **并行处理** - 多线程并行分析多个文件
* **增量缓存** - 基于文件内容哈希缓存结果, 二次运行只处理变更文件, 缓存目录默认为 `.ruff_cache`

[plantuml, "ruff check 的处理流水线", format=png]
----
@startuml
start
:读取源文件内容;
:词法分析与语法解析, 构建 CST;
:在 CST 上执行已启用的规则集合;
:收集诊断并计算安全修复;
if (开启了 --fix 且存在安全修复?) then (是)
  :将修复写回文件;
else (否)
  :仅输出诊断;
endif
:按文件内容哈希更新增量缓存;
stop
@enduml
----

=== 安装与子命令

本文以 **Ruff 0.16.6**(2026-09-03 发布)为例, 这是撰写时的最新稳定版. 安装方式任选其一:

[source,shell]
----
pip install ruff              # 通过 pip
uv add --dev ruff             # 通过 uv
brew install ruff             # 通过 Homebrew
cargo install ruff            # 通过 Cargo
ruff --version                # 验证安装
----

Ruff 仍采用 `0.x` 版本号, 但功能已稳定用于生产. 新规则先在 `--preview` 模式下预览, 若干版本后再默认启用.

[cols="1,5"]
|===
| 子命令 | 作用
| `ruff check` | 运行代码检查, 输出诊断并可选自动修复
| `ruff format` | 按规范风格格式化代码
| `ruff server` | 启动 Language Server, 供编辑器与 IDE 集成
| `ruff rule` | 查看指定规则的说明与示例, 如 `ruff rule F401`
| `ruff config` | 打印当前生效的完整配置
| `ruff clean` | 清空增量缓存
|===

=== ruff check - 代码检查

`ruff check` 默认启用 **E4, E7, E9, F** 四组规则, 覆盖 pycodestyle 的错误类与 pyflakes 全部规则, 能抓住未使用导入, 未使用变量, 未定义名称等最常见问题. 以一个包含多处问题的文件为例:

[source,python]
----
import json

def process(data):
    if data == None:
        return
    result = 0
    return data
----

[source,shell]
----
ruff check app.py
----

输出会逐行列出诊断, 带 `[*]` 标记的条目表示可自动修复:

[source,shell]
----
app.py:1:1: F401 [*] `json` imported but unused
app.py:4:12: E711 Comparison to `None` should be `cond is None`
app.py:6:5: F841 [*] Local variable `result` is assigned to but never used
Found 3 errors.
[*] 2 fixable with the `--fix` option.
----

常用修复与开发循环选项:

* `--fix` - 仅应用安全修复, 不改动可能有副作用的代码
* `--unsafe-fixes` - 连同不安全修复一起应用, 如删除可能被 `__all__` 引用的导入
* `--diff` - 预览将要产生的修改而不落盘
* `--watch` - 监听文件变化, 保存即自动重新检查, 适合本地开发

==== 抑制告警

单行抑制在行尾追加 `noqa` 注释并指定规则码:

[source,python]
----
import os  # noqa: F401
----

文件级抑制在文件顶部写入 `# ruff: noqa`(全部)或 `# ruff: noqa: F401, E501`(指定规则). 若某处 `noqa` 已无必要, 规则 `RUF100` 会提示移除.

=== ruff format - 代码格式化

`ruff format` 被设计为 **Black 的 drop-in 替代**, 对已按 Black 风格书写的代码保持稳定, 但并非保证逐字节一致. 示例如下:

[source,python]
----
def stats(values):
    return {
        "count": len(values), "sum": sum(values),
        "avg": sum(values)/len(values)
    }
----

执行格式化后, 规则统一为每项一行, 运算符两侧留空格, 并在闭合括号前补尾随逗号:

[source,shell]
----
ruff format stats.py
----

[source,python]
----
def stats(values):
    return {
        "count": len(values),
        "sum": sum(values),
        "avg": sum(values) / len(values),
    }
----

* `ruff format .` - 格式化整个目录
* `ruff format --check .` - 仅检查是否已格式化, 常用于 CI 门禁
* `ruff format --diff .` - 输出差异而不写文件

NOTE: 由于 formatter 已接管行长度与缩进等格式, 启用 formatter 的仓库无需再开启 `E501` 等格式类规则, Ruff 会自动跳过与格式化职责重叠的规则.

=== 配置与规则管理

配置可写在 `pyproject.toml` 的 `[tool.ruff]` 段, 也可用独立的 `ruff.toml`. 自 v0.2 起, lint 与 format 配置分别位于 `[tool.ruff.lint]` 与 `[tool.ruff.format]`:

[source,toml]
----
[tool.ruff]
line-length = 100
target-version = "py311"
extend-exclude = ["migrations"]      # <1>

[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B", "SIM", "S"]
ignore = ["E501"]                    # <2>

[tool.ruff.lint.per-file-ignores]
"tests/**" = ["S101"]                # <3>

[tool.ruff.format]
quote-style = "double"               # <4>
----

<1> 排除目录或文件, 也可在 `[tool.ruff.lint]` 下用 `exclude`
<2> 从已选规则中剔除个别规则
<3> 按文件路径覆盖规则, 如测试目录允许 `assert`
<4> 格式化时统一使用双引号

规则按前缀分组, 团队通常按需挑选几组组合启用. 常用前缀速查:

[cols="1,3,4"]
|===
| 前缀 | 来源 | 代表规则
| `E`, `W` | pycodestyle | `E501` 行过长, `W605` 无效转义序列
| `F` | pyflakes | `F401` 未使用导入, `F841` 未使用变量
| `I` | isort | `I001` 导入排序不当
| `UP` | pyupgrade | `UP032` 应使用 f-string
| `B` | flake8-bugbear | `B006` 可变对象作为默认参数
| `S` | flake8-bandit | `S101` 不应使用 `assert`
| `PTH` | flake8-use-pathlib | `PTH118` 应使用 `pathlib` 操作路径
| `PL` | pylint(部分) | `PLC0415` import 应位于模块顶部
| `RUF` | Ruff 特有 | `RUF100` 存在无效的 `noqa`
|===

若想抢先体验新规则, 可在 `[tool.ruff.lint]` 中开启 `preview = true`; 具体每条规则的说明用 `ruff rule 规则码` 查看.

=== 编辑器与 CI 集成

`ruff server` 实现了 **Language Server Protocol**, 是官方 Ruff 扩展(发布者为 `astral-sh`)与 VS Code Python 扩展的底层检查引擎, 支持保存时自动修复与格式化. 团队层面可用 pre-commit 在提交前拦截问题:

[source,yaml]
----
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.16.6
    hooks:
      - id: ruff
      - id: ruff-format
----

CI 中把 lint 与格式检查作为门禁, 阻断不合规代码合入:

[source,yaml]
----
steps:
  - run: pip install ruff==0.16.6
  - run: ruff check .
  - run: ruff format --check .
----

=== 总结

Ruff 用**单一 Rust 二进制**同时解决了 Python 工具链碎片化与性能两大痛点:

* **快** - 自研解析器 + 单遍执行 + 多线程 + 增量缓存, 比 `flake8` 快一到两个数量级
* **全** - 重实现 flake8 系, isort, pyupgrade, pylint 部分规则, 无需再装一堆插件
* **稳** - `ruff format` 对齐 Black 风格, 迁移平滑; 检查与格式化职责清晰分离
* **省** - 一处 `pyproject.toml` 配置全队生效, pre-commit 与 CI 一套命令搞定

实践建议: 统一用 `ruff check --fix` 做自动清理, 用 `ruff format` 做格式收口, 将 lint 与 format 检查接入 pre-commit 与 CI, 让规则收敛在配置文件中而非口头约定.
