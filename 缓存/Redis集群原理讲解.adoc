== Redis集群原理讲解

=== 高可用性: 故障转移

. **心跳与 Gossip 协议**
. **故障检测(PFAIL -> FAIL)**
. **从节点晋升**

=== 优势和局限性

优势::

* **自动分区:** 无需手动处理数据分布.

* **高可用性:** 内置主从复制和自动故障转移.

* **无缝扩展:** 可在线进行水平扩容和缩容.

局限性::

* **不支持多数据库:** 集群模式下只能使用 **db0**.

* **事务限制:** 所有 Key 必须位于同一个节点, 才能使用事务或 Lua 脚本. 可以使用**哈希标签**(Hash Tag) 来强制将多个 Key 放到同一个槽中(例如, user:{123}.profile 和 user:{123}.account 会被计算到同一个槽, 因为 CRC16 只计算 { 和 } 之间的部分 123).

* **批量操作限制:** 类似 MGET、MSET 等批量操作, 如果涉及的 Key 不在同一个节点, 无法直接使用. 同样可以通过哈希标签解决.

* **复制是异步的:** 在故障转移时, 可能丢失最后一次主从同步的写入数据.
