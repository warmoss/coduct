== Redis的Cuckoo filter原理讲解

接下来, 我们来详细讲解一下 Redis 中 Cuckoo Filter(布谷鸟过滤器)的原理.

首先, 要明确一点: **Redis 官方并未直接实现 Cuckoo Filter 这一数据结构.** 我们通常讨论的 Redis 布隆过滤器是通过 RedisBloom 这个官方模块提供的. 同样, Cuckoo Filter 也是作为 RedisBloom 模块的一部分功能提供的. 所以, 当我们说 "Redis 的 Cuckoo Filter" 时, 实际上指的是在 Redis 环境中, 通过 CF 命令系列操作的、由 RedisBloom 模块实现的 Cuckoo Filter.

接下来, 我们深入原理.

=== 为什么需要 Cuckoo Filter? -- 布隆过滤器的局限性

要理解 Cuckoo Filter, 必须先了解它的前辈--布隆过滤器.

布隆过滤器::

一个高效的概率性数据结构, 用于判断 "**某元素一定不存在**" 或 "**可能存在**" 于一个集合中. 它非常节省空间, 但有两个主要缺点:

. **不支持删除元素:** 这是它最大的痛点. 因为多个元素可能共享同一个位, 将某一位从 1 设为 0 可能会影响其他元素的判断.

. **查询性能相对固定:** 需要查询 k 个哈希函数对应的位.

Cuckoo Filter 就是为了解决 "**删除操作**" 这个问题而诞生的.

=== Cuckoo Filter 的核心思想

Cuckoo Filter 的设计灵感来源于 **布谷鸟的巢寄生行为**. 布谷鸟不会自己筑巢, 而是把蛋下到其他鸟的巢里, 让别的鸟代为孵化.

它的核心思想是:

. **使用一个桶(bucket)数组**作为底层存储, 每个桶可以存放多个**指纹(fingerprint)**.

. **指纹**是元素通过哈希计算后得到一个短的、固定大小的比特串(比如 8 比特). 它代表了该元素的"身份", 但信息量远小于元素本身.

. 每个元素在集合中会有 **两个可能的存储位置(桶)**. 这两个位置由两个哈希函数决定(在实际实现中, 通常用一个哈希函数衍生出两个).

. 当插入一个元素时, 它会检查这两个桶. 如果其中任何一个桶有空位, 就把它的指纹放进去. 如果两个桶都满了, 它会随机"踢走"其中一个桶里的一个现有指纹, 然后把新的指纹放进去.

. 被踢走的那个指纹不会消失, 它有自己的"另一个家". 于是, 它会被重新插入到它自己的另一个候选桶中. 这个过程可能会递归发生, 就像布谷鸟把别的蛋踢出鸟巢一样.

=== Cuckoo Filter 的工作原理详解

==== 数据结构

* **一个一维数组:** 这个数组被划分为很多个桶(Bucket).

* **每个桶(Bucket):** 有多个槽位(Slot), 通常每个桶有 4 个槽位. 每个槽位可以存放一个指纹.

[source, text, linenums]
----
Bucket 0: [ fp1, fp2, fp3, fp4 ]
Bucket 1: [ null, null, null, null ]
Bucket 2: [ fp5, null, fp6, null ]
...
Bucket N: [ ... ]
----

==== 哈希函数与位置计算

对于一个元素 x:

* **第一步: 计算两个候选桶索引**

** `h1 = hash(x)`

** `h2 = h1 XOR hash(fingerprint)`

** 注意: 这里巧妙的地方在于, 第二个位置 h2 是通过第一个位置 h1 和指纹的哈希值进行异或计算得到的. 这意味着, **只要你知道了 h1 和指纹, 你就能算出 h2; 反之, 知道了 h2 和指纹, 也能算出 h1**. 这个特性对于查找和删除至关重要.

* **第二步: 计算指纹**

** `fingerprint = fingerprint_hash(x)` 得到一个短的比特串, 比如 `1101 0110`

==== 操作流程

===== 插入(Insert)

. 计算 `x` 的 `h1` 和指纹 `f`.

. 计算 `h2 = h1 XOR hash(f)`.

. 检查桶 `h1` 和桶 `h2`:

** 如果任何一个桶有空槽位, 就将指纹 `f` 放入该空位, 插入成功.

** 如果两个桶都满了, 随机选择 `h1` 或 `h2` 桶, 从中随机踢出一个已存在的指纹 `f'`.

. 将新的指纹 `f` 放入被踢的槽位.

. 为被踢走的指纹 `f'` 寻找新家:

** 找到 `f'` 的另一个候选桶位置(因为 `f'` 的 `h1'` 已知, 可以算出它的 `h2'` ).

** 尝试将 `f'` 插入到它的另一个候选桶中.

** 如果另一个桶也满了, 就重复步骤 3-5, 踢走另一个指纹.

. 为了避免无限循环, 会设置一个最大踢出次数(比如 500 次). 如果达到最大次数, 则认为过滤器已满, 插入失败(或者可能触发扩容).

**这个过程就像一个连环踢, 直到所有指纹都找到自己的位置, 或者达到极限.**

===== 查找(Lookup)

. 计算 `x` 的 `h1` 和指纹 `f`.

. 计算 `h2 = h1 XOR hash(f)`.

. 检查桶 `h1` 和桶 `h2` 中是否存在指纹 `f`.

** 如果在任何一个桶中找到了 `f`, 则返回 "**可能存在**".

** 如果两个桶中都没有 `f`, 则返回 "**一定不存在**".

===== 删除(Delete)

这是 Cuckoo Filter 相比布隆过滤器的优势所在.

. 计算 `x` 的 `h1` 和指纹 `f`.

. 计算 `h2 = h1 XOR hash(f)`.

. 检查桶 `h1` 和桶 `h2`:

** 如果在任何一个桶中找到了指纹 f, **只需删除该指纹的一个实例**(注意: 同一个元素理论上不会在两个桶中同时存在, 但同一个指纹可能因哈希冲突来自不同元素, 所以通常只删一个).

** 删除成功.

** 如果没找到, 则说明该元素不在过滤器中.

==== 为什么可以删除?

因为 Cuckoo Filter 存储的是元素的"指纹", 并且每个指纹只存在于两个明确的、可计算的位置. 删除时, 我们精准地定位到这两个位置, 如果找到完全匹配的指纹, 就将其移除. 这不会影响其他任何元素的判断, 因为其他元素的指纹即使部分相同, 它们的候选桶位置也不同.

**注意:** 有一个极低概率的"指纹冲突"问题: 如果两个不同的元素 x 和 y 恰好在同一个桶中拥有相同的指纹, 那么删除 x 会导致 y 被误判为不存在. 但在指纹大小设置合理(如 8 位以上)时, 这个概率非常低.

=== 优缺点总结

优点::

* **支持动态删除操作:** 这是它相对于布隆过滤器最核心的优势.

* **更高的空间利用率:** 在相同的误判率下, Cuckoo Filter 通常比布隆过滤器更节省空间, 尤其是在负载因子(空间使用率)较高时.

* **查询效率高:** 只需要检查两个桶, 每个桶只有几个槽位, 查询性能稳定且高效.

缺点::

* **插入性能可能不稳定:** 在接近满载时, 插入可能会因为频繁的"踢出"操作而变慢, 最坏情况下插入会失败.

* **实现更复杂:** 逻辑比布隆过滤器复杂.

* **容量有上限:** 当过滤器快满时, 插入失败的概率会急剧上升, 而布隆过滤器只是误判率升高.

=== 在 Redis 中的使用(RedisBloom Module)

在 Redis 中, 你可以通过 `CF` 命令族来使用 Cuckoo Filter:

[source, bash, linenums]
----
# 创建一个 Cuckoo Filter, 初始分配 10000 个项目的容量
CF.RESERVE my_cuckoo_filter 10000

# 向过滤器中添加元素
CF.ADD my_cuckoo_filter "apple"
CF.ADD my_cuckoo_filter "banana"

# 检查元素是否存在
CF.EXISTS my_cuckoo_filter "apple" # 返回 1 (存在)
CF.EXISTS my_cuckoo_filter "grape" # 返回 0 (不存在)

# 从过滤器中删除元素
CF.DEL my_cuckoo_filter "apple"
----

=== 总结

Cuckoo Filter 是一种巧妙的数据结构, 它通过 "**两个候选桶**" 和 "**指纹踢出**" 的机制, 在保持布隆过滤器空间效率优势的同时, 成功实现了对元素的 **删除功能**. 它解决了布隆过滤器在需要动态删除场景下的痛点, 是概率性过滤器的一个重要演进. 当你在 Redis 中需要一个支持删除的、高效的"是否存在"判断器时, Cuckoo Filter 是一个非常优秀的选择.
