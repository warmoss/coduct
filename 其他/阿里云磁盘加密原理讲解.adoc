== 阿里云磁盘加密原理讲解

阿里云ECS云盘加密是一种**透明加密**技术, 在数据写入磁盘时自动加密, 读取时自动解密, 对上层应用**完全透明**. 其核心依托于**KMS密钥管理服务**和**AES-256加密算法**, 是云上数据静态加密的基础设施.

=== 为什么需要云盘加密

云盘加密主要解决以下安全问题:

* **物理介质泄露:** 云服务商使用的物理磁盘被回收、维修或退役时, 数据可能被恢复
* **快照泄露:** 未经加密的快照如果被非法复制或共享, 其中包含的数据可直接被读取
* **镜像泄露:** 自定义镜像被共享或导出后, 其中的敏感数据面临泄露风险
* **合规要求:** 等保2.0、GDPR、PCI DSS等行业法规均要求对存储的敏感数据进行加密

TIP: 云盘加密一旦开启**无法关闭**, 且必须在创建云盘时决定是否加密. 因此建议生产环境默认开启加密.

=== 核心概念

云盘加密:: 指对ECS云服务器所挂载的**块存储设备**(系统盘和数据盘)进行透明加密, 加密操作由**云平台底层驱动**完成, 不侵入用户操作系统
透明加密:: 加密和解密过程对上层应用和文件系统完全透明, 不需要修改任何应用程序代码
密钥材料(Key Material):: 实际用于AES-256加密操作的原始密钥数据, 在KMS中由主密钥派生
数据密钥(Data Encryption Key, DEK):: 由KMS生成的一次性对称密钥, 用于加密具体云盘的数据
主密钥(Customer Master Key, CMK):: 存储在KMS **HSM**(Hardware Security Module)中的根密钥, 用于加密DEK, 本身从不离开HSM

云盘加密的完整体系涉及三个层面:

. **ECS宿主机层:** 负责拦截IO请求, 在数据落盘前加密、读取后解密
. **KMS服务层:** 负责管理主密钥和生成数据密钥, 是加密体系的安全锚点
. **OSS存储层:** 加密快照和加密镜像的底层存储介质

=== 加密算法与密钥体系

==== 加密算法

阿里云云盘加密采用 **AES-256** 对称加密算法, 使用 **XTS(XEX-based Tweaked CodeBook mode with ciphertext Stealing)** 工作模式.

XTS模式是针对**块存储设备**专门设计的加密模式, 具备以下特性:

* **每个数据块使用独立 tweak 值**, 相同明文在不同位置产生不同密文 <1>
* 支持**随机读写**, 加密单个数据块不影响其他块 <2>
* 使用**两个密钥**: 一个用于AES加密, 一个用于tweak生成 <3>

[source]
----
// 每个LBA(Logical Block Address)扇区加密公式:
C = AES_enc(K1, P XOR Tweak) XOR Tweak <1> <2> <3>
// 其中 Tweak = AES_enc(K2, LBA) * alpha^j
// K1 - 数据加密密钥, K2 - tweak密钥
// LBA - 逻辑块地址, j - 块内扇区索引
----

<1> 避免相同数据块产生相同密文, 抵御字典攻击
<2> 这是磁盘加密的关键特性, 确保任意位置独立加解密
<3> 两个密钥均由KMS生成的数据密钥派生

==== 密钥体系设计

阿里云盘加密采用**两层密钥体系**:

[cols="2,2,4"]
|===
| 密钥层级 | 存储位置 | 说明

| **主密钥(CMK)** | KMS HSM | 用户创建或系统默认, 永不离开HSM; 支持自动轮转
| **数据密钥(DEK)** | ECS宿主机内存 | 由KMS通过CMK加密生成, 存储在宿主机内存中; 定期刷新

|===

每次宿主机重启或云盘重新挂载时, 系统会重新向KMS申请DEK. DEK在内存中以**明文**形式缓存, 用于加解密IO请求.

WARNING: DEK明文仅在ECS宿主机物理内存中, 不会写入磁盘或swap分区. 若宿主机内存被非法读取, 敏感数据面临泄露风险.

=== 工作流程

==== 创建加密云盘

. **用户指定密钥:** 选择"默认密钥(阿里云自动托管)"或"自定义密钥(用户KMS CMK)"
. **KMS授权检查:** 系统检查ECS服务是否具有使用指定CMK的权限
. **写入元数据:** 在云盘元数据中标记"已加密"及关联的CMK ID, 但不存储密钥本身
. **生成DEK:** 当云盘首次挂载到ECS实例时, 宿主机调用KMS生成DEK

==== 数据读写流程

[plantuml,"数据读写加密流程",format=png]
----
@startuml
participant "应用进程" as app
participant "操作系统" as os
participant "ECS宿主机驱动" as driver
database "KMS" as kms
database "云盘" as disk

== 写入流程 ==
app -> os: write(fd, buf, len)
os -> driver: IO请求(LBA, 明文数据)
driver -> driver: 使用DEK进行AES-256-XTS加密
driver -> disk: 写入密文数据

== 读取流程 ==
app -> os: read(fd, buf, len)
os -> driver: IO请求(LBA)
driver -> disk: 读取密文数据
driver -> driver: 使用DEK进行AES-256-XTS解密
driver -> os: 返回明文数据
os -> app: 返回
@enduml
----

从上述流程可以看出:

* **应用无感知:** 应用进程读写普通文件即可, 无需关心加密细节
* **逐扇区加密:** 加密粒度是**512字节扇区**, 每次IO请求仅加密/解密涉及的扇区
* **零存储开销:** 加密不增加存储空间占用, 密文长度等于明文长度

==== DEK获取与缓存

. **挂载触发:** ECS实例启动或云盘挂载时, 宿主机Hypervisor检测到云盘加密标识
. **调用KMS:** 宿主机通过内部Endpoint调用 `GenerateDataKey`, 参数包含CMK ID
. **返回加密DEK:** KMS返回 `Plaintext(明文DEK)` 和 `CiphertextBlob(密文DEK)`
. **内存缓存:** 明文DEK缓存于宿主机内核内存中, 密文DEK随云盘元数据持久化
. **周期性刷新:** 明文DEK有存活时间(TTL), 过期后使用密文DEK重新解密获取

[source,shell]
----
# 通过阿里云CLI创建加密云盘
aliyun ecs CreateDisk --DiskName encrypted-data-disk \\
  --Size 20 --Encrypted true --KMSKeyId <CMK-ID>
  
# 查看云盘加密信息
aliyun ecs DescribeDisks --DiskIds '["d-xxxxx"]' \\
  --query 'Disks.Disk[0].{Encrypted:Encrypted,KMSKeyId:KMSKeyId}'
----

=== 快照与镜像加密

==== 加密快照

创建加密云盘的快照时, 快照数据**继承云盘的加密状态**:

* 快照使用创建快照时云盘的DEK进行加密存储
* 快照被用于创建新云盘时, 新云盘自动使用相同的CMK加密
* 快照数据以加密形式存储在OSS中

==== 加密镜像

自定义镜像支持加密功能:

* 来源为加密云盘的系统盘快照, 镜像自动继承加密属性
* 使用加密镜像创建的ECS实例, 其系统盘自动开启加密
* 加密镜像跨地域复制时, 可以使用目标地域的KMS CMK重新加密

=== 性能影响

云盘加密对性能的影响主要来自两方面:

* **CPU开销:** AES-256-XTS加解密需要消耗CPU资源. 现代服务器CPU支持**AES-NI**(Advanced Encryption Standard New Instructions)指令集, 可硬件加速加解密, 性能损耗极低
* **IO延迟:** 每次读写增加一次加密/解密操作, 引入微妙级延迟. 典型场景下性能损耗小于**3%-5%**

[cols="1,2,3"]
|===
| 场景 | 吞吐量(顺序读写) | IOPS(随机读写)
| 未加密云盘 | 基准值 | 基准值
| 加密云盘(有AES-NI) | 基准值的95%-98% | 基准值的95%-97%
| 加密云盘(无AES-NI) | 基准值的70%-80% | 基准值的60%-70%
|===

TIP: 对于生产环境的高IO场景, 建议选用支持AES-NI的CPU实例规格, 以最小化加密带来的性能损耗.

=== 最佳实践

. **生产环境默认加密:** 建议对全部生产环境的系统盘和数据盘开启加密, 通过RAM策略强制要求
. **使用自定义CMK:** 相比默认密钥, 自定义CMK支持**禁用、启用、轮转和权限控制**, 建议为不同环境(开发/测试/生产)使用不同的CMK
. **启用密钥轮转:** 为CMK开启**自动轮转**(默认一年一次), 定期更换根密钥
. **权限分离:** 使用RAM策略实现密钥管理员和数据操作员的职责分离
. **跨地域备份注意密钥:** 跨地域复制加密快照时, 确保目标地域有相应的KMS CMK可用

[source,json]
----

----

=== 与相关服务的关系

云盘加密并非独立功能, 而是与多个阿里云服务协作:

* **KMS:** 提供密钥生成、存储和管理能力, 是云盘加密的安全基石
* **ECS:** 提供加密能力的宿主机侧实现, 集成AES-NI硬件加速
* **OSS:** 存储加密快照和加密镜像的底层基础设施
* **RAM:** 控制谁可以使用哪些密钥创建加密云盘, 实现权限管控

更详细的KMS原理请参考 <<KMS密钥管理服务讲解.adoc, KMS密钥管理服务讲解>>, AES算法细节请参考 <<../安全算法/aes讲解.adoc, AES讲解>>.

=== 总结

阿里云云盘加密通过**透明加密**技术, 结合**AES-256-XTS**算法和**KMS密钥管理服务**, 为云上数据提供了高效、安全的静态加密能力. 其核心价值在于:

* **零侵入:** 应用无需改造, 加密完全透明
* **强安全:** 使用业界标准的AES-256-XTS, 密钥由HSM保护
* **高性能:** AES-NI硬件加速下性能损耗极低
* **易管理:** 通过RAM和KMS实现密钥的集中管理和权限控制
