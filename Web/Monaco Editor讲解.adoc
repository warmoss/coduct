== Monaco Editor讲解

在浏览器里做代码编辑, 难点从来不是"能输入文字", 而是语法着色, 补全, 诊断, 大文件滚动, 多光标与撤销栈这些细节. **Monaco Editor** 是 VS Code 编辑器内核的独立发行版, 把这些能力以 npm 包的形式提供给任意 Web 应用. 本文基于最新稳定版 0.58.0, 讲解其模型与视图的分离, worker 语言服务, ESM 打包形态, 以及扩展语言能力和接入 LSP 的方式.

参考: <<其他/LSP协议讲解.adoc#, LSP协议讲解>>, <<Web/node/vite原理讲解.adoc#, vite原理讲解>>

[[monaco-what]]
=== Monaco Editor 是什么

**Monaco Editor**:: 微软开源的浏览器代码编辑器, 源码由 VS Code 仓库生成, 以 MIT 协议发布, 只提供编辑区能力, 不含文件系统, 终端与插件宿主.
**独立编辑器 (standalone editor)**:: 脱离 VS Code 宿主运行的模式, 通过 `monaco.editor.create` 创建, 用命名空间 `monaco` 操作.
**模型 (model)**:: 一份文本文档, 包含内容, 语言, 版本号与撤销栈, 由 `monaco.editor.createModel` 创建, 可被多个编辑器实例共享.
**编辑器实例 (editor)**:: 绑定到某个 DOM 容器的视图, 持有光标, 选区, 滚动位置与装饰等视图状态.
**贡献 (contribution)**:: 功能的注册单元, 如查找, 补全, 折叠, 括号匹配; 每个贡献在注册时挂载命令与监听器.
**Monarch**:: 声明式词法高亮 DSL, 用状态机描述 token 规则, 不需要完整的语法分析器.
**worker**:: 后台线程, 承载 TypeScript 语言服务, JSON 校验, 差异计算等 CPU 密集任务.

与 VS Code 同源意味着编辑体验一致, 但也意味着**只做编辑器**: 打开文件, 保存, 多标签页, 扩展市场都需要应用自己实现. 若只需要编辑几行配置, 它属于明显的过度设计; 若要构建"类 IDE"的在线编辑, 它是最省事的起点.

[[monaco-why]]
=== 为什么选择 Monaco Editor

**优势**:

* **与 VS Code 同源:** 编辑体验, 快捷键, 主题与 VS Code 一致, 用户几乎没有学习成本
* **开箱语言能力:** TypeScript, JavaScript, JSON, CSS, HTML 自带语言服务, 含补全, 诊断, 格式化, 符号
* **完整编辑特性:** 多光标, 查找替换, 折叠, 括号着色, 粘性滚动, 内联提示, 差异对比
* **可编程扩展:** provider, 装饰, 命令, 主题, 自定义 tokenizer 都可通过 API 注入
* **可访问性:** 支持屏幕阅读器模式与高对比主题, 这是多数轻量编辑器缺失的部分

**代价**:

* **体积大:** 全量主包约 4.1 MB (gzip 约 1.07 MB), 必须按需注册才能控制首屏
* **必须打包:** 0.53 起 AMD 构建废弃, 需要 ESM 打包器并正确注册 worker
* **仅面向桌面浏览器:** 官方不支持移动端触屏交互
* **不是框架组件:** 生命周期, 状态同步, 布局自适应都要自己封装
* **LSP 支持较新:** 0.55 才引入原生 `monaco.lsp`, 能力仍在完善

一句话决策: 需要"VS Code 级"编辑体验且面向桌面端, 选 Monaco; 只需要轻量文本域增强, 选 CodeMirror 6 更划算.

[[monaco-arch]]
=== 整体架构

Monaco 沿用 VS Code 的分层设计: API 层只做门面, 编辑内核负责文本与视图, 语言能力下沉到 worker, 功能以贡献的形式按需挂载.

[plantuml, "Monaco Editor 整体架构", format=png]
----
@startuml
package "应用层" {
  [业务代码 / 框架封装] as APP
}
package "API 层" {
  [monaco.editor] as EDITOR_API
  [monaco.languages] as LANG_API
  [monaco.lsp] as LSP_API
  [monaco.typescript / json / css / html] as FEAT_API
}
package "编辑内核" {
  [TextModel 文本模型] as MODEL
  [ViewModel 视图模型] as VM
  [View 渲染与输入] as VIEW
  [Contributions 功能贡献] as CONTRIB
}
package "语言层" {
  [Monarch 词法着色] as MONARCH
  [语言服务客户端] as LSCLIENT
}
package "后台线程" {
  [editor.worker 通用计算] as EW
  [ts.worker] as TSW
  [json.worker] as JW
  [css.worker / html.worker] as CW
}
[语言服务器 LSP Server] as LS

APP --> EDITOR_API
APP --> LANG_API
APP --> LSP_API
APP --> FEAT_API
EDITOR_API --> MODEL
EDITOR_API --> VIEW
MODEL --> VM
VM --> VIEW
EDITOR_API --> CONTRIB
LANG_API --> MONARCH
LANG_API --> LSCLIENT
LSCLIENT <--> TSW
LSCLIENT <--> JW
LSCLIENT <--> CW
EDITOR_API <--> EW
LSP_API <--> LS: JSON-RPC
@enduml
----

各层职责:

* **API 层:** `monaco.editor` 与 `monaco.languages` 是稳定门面, 内部转发到服务容器; 应用只依赖这一层.
* **编辑内核:** 三段式 MVVM. `ITextModel` 只描述文本与元数据; `ViewModel` 负责 Tab 展开, 折行, 装饰投影等派生状态; `View` 负责 DOM 渲染, 滚动与输入.
* **贡献层:** 查找, 补全, 折叠等功能各自注册命令与监听器, 0.56 起可以按功能单独引入.
* **语言层:** 词法着色在 UI 线程完成, 语法与语义分析通过语言服务协议交给 worker.
* **worker 层:** 与主线程隔离, 避免类型检查或 diff 计算阻塞输入响应.

模型与视图分离带来一个直接好处: **同一份模型可以挂到多个编辑器**, 内容实时同步, 光标与滚动互不干扰.

[source,typescript,linenums]
----
const model = monaco.editor.createModel(
  'const answer: number = 42;',
  'typescript',
  monaco.Uri.parse('inmemory://demo/main.ts')
);

const left = monaco.editor.create(document.getElementById('left')!, { model });
const right = monaco.editor.create(document.getElementById('right')!, {
  model,
  readOnly: true,
  theme: 'vs-dark'
});
----

worker 按 `label` 分发, 不同语言对应不同线程:

[cols="2,3,4"]
|===
|label
|worker 入口
|职责

|默认
|`editor/editor.worker`
|差异计算, 链接识别, 基于单词的补全, 通用文本算法

|`json`
|`languages/features/json/json.worker`
|JSON 校验, schema 补全, 格式化

|`css`, `scss`, `less`
|`languages/features/css/css.worker`
|CSS 诊断, 补全, 格式化

|`html`, `handlebars`, `razor`
|`languages/features/html/html.worker`
|HTML 诊断, 补全, 格式化

|`typescript`, `javascript`
|`languages/features/typescript/ts.worker`
|TypeScript 语言服务, 类型检查, 补全, 重构

|===

一次补全请求的完整路径:

[plantuml, "语言服务调用时序", format=png]
----
@startuml
actor 用户 as U
participant "编辑器 (UI 线程)" as E
participant "语言服务客户端" as C
participant "worker 线程" as W

U -> E: 输入字符
E -> C: 触发补全 provider
C -> W: 请求 (文档版本, 位置)
W -> W: 解析与类型检查
W --> C: 候选列表
C --> E: 转换为 CompletionItem
E --> U: 渲染下拉列表
@enduml
----

NOTE: 语言服务拿到的文档由客户端同步推送, worker 不直接读取 DOM 或文件系统. 这也是大文件编辑不会因为类型检查而卡顿的原因.

[[monaco-package]]
=== 版本演进与打包形态

0.53 是分水岭: AMD 构建被标记为废弃, 官方只支持 ESM, 并明确要求配合打包器使用. 之后的版本持续重组入口, 到 0.56 形成了按功能与语言拆分的新结构.

[cols="2,5"]
|===
|版本
|关键变化

|0.52 及以前
|同时提供 AMD 与 ESM, 可直接用 `<script>` 引入

|0.53
|AMD 标记为废弃, 内部 AMD 模块不再可访问, 自定义 AMD worker 失效

|0.55
|语言服务命名空间上移 (`monaco.typescript` 等); 引入原生 `monaco.lsp`

|0.56
|ESM 入口重组, 支持按功能与语言按需注册; 新增 `advanced-external` 与 `advanced-wasm` 差异算法

|0.57
|新增 `editor.wordWrapIndicator`, `editor.fullwidthCharacterWidth`, `languages.score`

|0.58
|Markdown 中的远程图片默认不加载; editor worker 内置 `@vscode/diff` 后端

|===

0.56 起的公开入口:

[cols="3,4"]
|===
|入口
|内容

|`monaco-editor`
|全部功能与全部语言, 等价于旧版行为

|`monaco-editor/editor`
|仅编辑器 API (`editor`, `languages`, `Uri`, `Range`, `KeyMod` 等)

|`monaco-editor/features/register.all`
|全部编辑功能贡献

|`monaco-editor/features/<feature>/register`
|单个功能, 如 `find`, `suggest`, `folding`

|`monaco-editor/languages/definitions/register.all`
|全部基础语言的定义与着色

|`monaco-editor/languages/definitions/<language>/register`
|单个基础语言, 如 `go`, `python`

|`monaco-editor/languages/features/register.all`
|JSON, CSS, HTML, TypeScript 语言服务

|`monaco-editor/languages/features/<language>/register`
|单个语言服务, 如 `json`

|===

worker 也走同样的子路径:

[cols="2,4"]
|===
|worker
|入口

|通用
|`monaco-editor/editor/editor.worker`

|JSON
|`monaco-editor/languages/features/json/json.worker`

|CSS
|`monaco-editor/languages/features/css/css.worker`

|HTML
|`monaco-editor/languages/features/html/html.worker`

|TypeScript
|`monaco-editor/languages/features/typescript/ts.worker`

|===

[WARNING]
====
`package.json` 的 `exports` 只映射新路径. 旧写法 `monaco-editor/esm/vs/editor/editor.worker` 会被拼接成 `esm/vs/esm/vs/editor/editor.worker.js`, 打包时报 "Failed to resolve entry".

旧版示例中常见的 `monaco-editor/esm/vs/editor/editor.api` 同样需要改为 `monaco-editor/editor/editor.api`.
====

NOTE: 包内仍保留 `min/vs` 的 AMD 产物供 CDN 场景使用, 但官方不再支持该形态, 新项目应直接使用 ESM.

[[monaco-quickstart]]
=== 快速开始

以 Vite 为例, 完整流程只有三步.

. **安装依赖**
+
[source,shell]
----
npm install monaco-editor
----

. **注册 worker**
+
worker 必须先于编辑器创建注册, 否则语言服务不可用:
+
[source,typescript,linenums]
----
// src/monaco.ts
import * as monaco from 'monaco-editor'
import EditorWorker from 'monaco-editor/editor/editor.worker?worker'
import JsonWorker from 'monaco-editor/languages/features/json/json.worker?worker'
import CssWorker from 'monaco-editor/languages/features/css/css.worker?worker'
import HtmlWorker from 'monaco-editor/languages/features/html/html.worker?worker'
import TsWorker from 'monaco-editor/languages/features/typescript/ts.worker?worker'

self.MonacoEnvironment = {          // <1>
  getWorker(_workerId: string, label: string) {
    switch (label) {
      case 'json':
        return new JsonWorker()
      case 'css':
      case 'scss':
      case 'less':
        return new CssWorker()
      case 'html':
      case 'handlebars':
      case 'razor':
        return new HtmlWorker()
      case 'typescript':
      case 'javascript':
        return new TsWorker()
      default:
        return new EditorWorker()
    }
  }
}

export default monaco
----
+
<1> Vite 的 `?worker` 后缀把 worker 单独打包并返回构造函数; 同时定义 `getWorker` 与 `getWorkerUrl` 时, 前者优先.

. **创建编辑器**
+
[source,typescript,linenums]
----
import monaco from './monaco'

const editor = monaco.editor.create(document.getElementById('editor')!, {
  value: 'const answer: number = 42;',
  language: 'typescript',
  theme: 'vs-dark',
  automaticLayout: true,            // <1>
  minimap: { enabled: false }
})
----
+
<1> 容器尺寸变化时自动重排. 若容器由动画改变尺寸, 手动调用 `editor.layout()` 更可控.

常用构造选项:

[cols="3,5"]
|===
|选项
|说明

|`value` / `language`
|初始文本与语言, 与 `model` 二选一

|`model`
|复用已有文本模型

|`theme`
|`vs`, `vs-dark`, `hc-black`, `hc-light`

|`readOnly` / `domReadOnly`
|逻辑只读 / 同时禁止 DOM 层编辑

|`automaticLayout`
|监听容器尺寸并自动布局

|`fontSize` / `fontFamily`
|字号与字体

|`wordWrap`
|`off`, `on`, `wordWrapColumn`, `bounded`

|`scrollBeyondLastLine`
|允许滚动到末行之后

|`minimap.enabled`
|是否显示缩略图

|`ariaLabel`
|可访问性标签

|===

TIP: TypeScript 项目需要在 `tsconfig.json` 中引入 `vite/client` 类型, 否则 `?worker` 导入没有类型声明, 可写 `"types": ["vite/client"]`.

[[monaco-model]]
=== 模型与编辑器实例

编辑器的状态分成两份:

* **模型持有内容:** 文本, 语言, 版本号, 撤销栈, 标记, 以及所有与"文档"相关的数据
* **实例持有视图:** 光标, 选区, 滚动位置, 折叠状态, 装饰集合

因此正确的切换方式是 `editor.setModel(nextModel)`, 而不是销毁编辑器重建. 语言也可以在运行时切换:

[source,typescript,linenums]
----
const model = monaco.editor.createModel(code, 'typescript', uri)

const editor = monaco.editor.create(container, { model, automaticLayout: true })

const sub = model.onDidChangeContent(() => {        // <1>
  console.log(model.getLineCount(), model.getValueLength())
})

monaco.editor.setModelLanguage(model, 'json')       // <2>

sub.dispose()
editor.dispose()
model.dispose()                                     // <3>
----

<1> 监听内容变化做自动保存或脏标记; 需要区分编辑来源时用 `onDidChangeContent` 的事件对象
<2> 语言变化会触发重新着色与对应语言服务挂载
<3> 先释放编辑器, 再释放模型; 顺序反了会留下悬挂的视图引用

常用模型 API:

[cols="3,5"]
|===
|API
|用途

|`getValue()` / `setValue()`
|读写全文; `setValue` 会清空撤销栈

|`getValueInRange()` / `applyEdits()`
|区间读取与批量编辑

|`getOffsetAt()` / `getPositionAt()`
|偏移与行列互转

|`pushEditOperations()`
|带光标与选区恢复的编辑

|`getLanguageId()`
|当前语言

|`getLineCount()` / `getLineMaxColumn()`
|行数与行宽

|`onDidChangeContent`
|内容变化事件

|===

URI 不只是唯一标识. 它会参与语言推断, 并作为 worker 内的文件路径, 影响模块解析与 `@types` 查找:

[source,typescript]
----
monaco.Uri.parse('file:///src/main.ts')
monaco.Uri.parse('inmemory://model/1')
----

NOTE: 打开过的模型不会自动回收. 长会话应用应在关闭文件时 `dispose` 模型, 并用 `monaco.editor.getModels()` 排查泄漏.

==== 自定义词法着色

Monarch 用状态机描述 token, 适合日志, DSL, 配置等小语言:

[source,typescript,linenums]
----
monaco.languages.register({ id: 'applog' })

monaco.languages.setMonarchTokensProvider('applog', {
  tokenizer: {
    root: [
      [/^\d{4}-\d{2}-\d{2}/, 'number.date'],       // <1>
      [/\b(ERROR|FATAL)\b/, 'keyword'],
      [/\b(WARN)\b/, 'type'],
      [/\bINFO\b/, 'string'],
      [/\[[^\]]*\]/, 'annotation']                // <2>
    ]
  }
})
----

<1> 正则匹配到的时间戳被标为 `number.date`, 可在主题中单独配置颜色
<2> 方括号内容标为 `annotation`, token 名称可自定义

==== 配置内置语言服务

TypeScript 与 JSON 的语言服务通过各自的 defaults 对象配置, 0.55 起位于顶层命名空间:

[source,typescript,linenums]
----
monaco.typescript.typescriptDefaults.setCompilerOptions({
  target: monaco.typescript.ScriptTarget.ES2020,
  moduleResolution: monaco.typescript.ModuleResolutionKind.NodeJs,
  strict: true,
  noEmit: true
})

monaco.typescript.typescriptDefaults.addExtraLib(
  'declare interface Window { appConfig: Record<string, string> }',
  'file:///types/global.d.ts'
)

monaco.json.jsonDefaults.setDiagnosticsOptions({
  validate: true,
  enableSchemaRequest: true,
  schemas: [{
    uri: 'https://example.com/schema/app.json',
    fileMatch: ['*'],
    schema: {
      type: 'object',
      required: ['name'],
      properties: { name: { type: 'string' } }
    }
  }]
})
----

NOTE: 0.55 之前写作 `monaco.languages.typescript.typescriptDefaults`, 升级时命名空间需要整体替换. 可用的 `ScriptTarget` 只到 `ES2020` 与 `ESNext`, 不要照搬 tsconfig 中的新枚举.

带代码片段的补全示例:

[source,typescript,linenums]
----
monaco.languages.registerCompletionItemProvider('applog', {
  triggerCharacters: [' '],
  provideCompletionItems(model, position) {
    const word = model.getWordUntilPosition(position)
    const range = {
      startLineNumber: position.lineNumber,
      endLineNumber: position.lineNumber,
      startColumn: word.startColumn,
      endColumn: word.endColumn
    }

    return {
      suggestions: [{
        label: 'error-with-code',
        kind: monaco.languages.CompletionItemKind.Snippet,
        insertText: 'ERROR [${1:CODE}] ${2:message}',
        insertTextRules:
          monaco.languages.CompletionItemInsertTextRule.InsertAsSnippet,
        documentation: '插入带错误码的日志行',
        range
      }]
    }
  }
})
----

==== 诊断与标记

诊断通过标记 (marker) 展示, 一个模型可以同时挂多个来源的标记:

[source,typescript,linenums]
----
monaco.editor.setModelMarkers(model, 'applog-lint', [{   // <1>
  severity: monaco.MarkerSeverity.Error,
  message: '未知的日志级别',
  startLineNumber: 3,
  startColumn: 1,
  endLineNumber: 3,
  endColumn: 12
}])
----

<1> 第二个参数是 owner; 同名 owner 的标记会被整体覆盖, 不同来源务必使用不同 owner

NOTE: 标记不是装饰. 标记归属于模型并展示在行号区与概览标尺, 装饰归属于编辑器或模型区间, 可以改变行背景与内联样式, 两者用途不同.

[WARNING]
====
0.58 起, 悬停, 补全详情, 参数提示等位置渲染的 Markdown 默认**不加载远程图片**, 只允许 `data:` 图片.

若 provider 返回带外链图片的文档, 需要显式放行: `markdownImages: { allowedOrigins: ['https://img.shields.io'] }`, 或设为 `true` 恢复旧行为.
====

[[monaco-lsp]]
=== 接入 LSP

内置 provider 只覆盖少数语言. 要让 Monaco 获得与 VS Code 接近的多语言能力, 标准做法是接入语言服务器, 协议细节见 <<其他/LSP协议讲解.adoc#, LSP协议讲解>>.

0.55 起 Monaco 内置了 `monaco.lsp` 命名空间, 0.56 补齐了类型化的客户端与传输层:

[source,typescript,linenums]
----
import * as monaco from 'monaco-editor'

const transport = await monaco.lsp.WebSocketTransport.connectTo({
  host: 'localhost',
  port: 3000
})

const client = new monaco.lsp.MonacoLspClient(transport, {
  allowedLocalCommands: ['editor.action.formatDocument']   // <1>
})
----

<1> 语言服务器可触发的本地命令白名单. 服务器输出视为不可信输入, 只放行确定安全的命令

三种方案对比:

[cols="2,3,3,3"]
|===
|方案
|优点
|限制
|适用

|`monaco.lsp`
|内置, 类型完整, 无需额外依赖
|能力集合固定, 构造即初始化, 未暴露 `dispose`
|简单场景, 自研服务器

|`monaco-languageclient`
|功能完整, 与 VS Code 语言客户端同源
|依赖多, 包体积大, 版本需与 Monaco 对齐
|生产级多语言 IDE

|自研 provider
|完全可控, 体积最小
|只覆盖点状能力, 协议细节自担
|单一 DSL

|===

[IMPORTANT]
====
`MonacoLspClient` 在构造时立即发送 `initialize`, 并对所有文本模型挂载补全, 悬停, 跳转, 诊断等特性. 它目前没有公开的释放方法, 页面级复用时应把客户端与编辑器宿主放在同一生命周期内, 由路由卸载统一回收连接.
====

[[monaco-decoration]]
=== 装饰, 标记与命令

装饰用于把业务状态画到编辑器上, 例如错误行高亮, 断点, 搜索结果, 代码审查意见. 与标记的差异:

[cols="2,4,4"]
|===
|维度
|装饰 (decoration)
|标记 (marker)

|归属
|编辑器或模型区间
|模型, 按 owner 分组

|用途
|行背景, 行号图标, 内联样式
|诊断信息 (错误, 警告)

|更新方式
|集合整体替换
|同名 owner 整体覆盖

|常见 API
|`createDecorationsCollection`
|`setModelMarkers`

|===

[source,typescript,linenums]
----
const decorations = editor.createDecorationsCollection([{
  range: new monaco.Range(3, 1, 3, 24),
  options: {
    isWholeLine: true,
    className: 'line-error',                 // <1>
    glyphMarginClassName: 'glyph-error',
    hoverMessage: { value: '**SyntaxError** 缺少分号' },
    overviewRuler: {
      color: '#f14c4c',
      position: monaco.editor.OverviewRulerLane.Right
    }
  }
}])

decorations.set([/* 新的装饰数组 */])
decorations.clear()
----

<1> 类名作用于 Monaco 自己创建的 DOM 节点, 样式必须写在全局作用域, 组件库的 scoped 样式不会生效

命令与快捷键通过 `addAction` 注册, 可同时进入右键菜单:

[source,typescript,linenums]
----
editor.addAction({
  id: 'app.saveDraft',
  label: '保存到草稿',
  keybindings: [monaco.KeyMod.CtrlCmd | monaco.KeyCode.KeyS],   // <1>
  contextMenuGroupId: 'navigation',
  run: (ed) => saveDraft(ed.getValue())
})
----

<1> 组合键用位或拼接, `CtrlCmd` 在 Windows/Linux 为 Ctrl, 在 macOS 为 Command

NOTE: 不需要菜单项时用 `editor.addCommand`; 需要按上下文启用或禁用时, 配合 `precondition` 与上下文键.

[[monaco-diff]]
=== 差异编辑器

差异编辑器复用同一套内核, 内部持有原稿与改稿两个编辑器, 由独立算法计算区间映射:

[source,typescript,linenums]
----
const diffEditor = monaco.editor.createDiffEditor(container, {
  renderSideBySide: true,
  ignoreTrimWhitespace: false,
  diffAlgorithm: 'advanced-wasm',      // <1>
  automaticLayout: true
})

diffEditor.setModel({ original, modified })

const modifiedEditor = diffEditor.getModifiedEditor()
modifiedEditor.updateOptions({ readOnly: true })
----

<1> 0.56 起支持 `advanced-external` 与 `advanced-wasm`; 0.58 把 `@vscode/diff` 后端打包进 editor worker, 计算失败时回退到内置算法

[cols="3,5"]
|===
|选项
|说明

|`renderSideBySide`
|并排或内联展示

|`useInlineViewWhenSpaceIsLimited`
|空间不足时自动切内联

|`ignoreTrimWhitespace`
|忽略空白差异

|`diffAlgorithm`
|`legacy`, `advanced`, `advanced-external`, `advanced-wasm`

|`renderOverviewRuler`
|是否显示概览标尺

|===

NOTE: 两个子编辑器可以通过 `getOriginalEditor()` 与 `getModifiedEditor()` 取用, 但不要再给它们 `setModel` 其他模型, 差异映射会失效.

[[monaco-theme]]
=== 主题与外观

主题由基础主题, token 规则与界面颜色三部分组成:

[source,typescript,linenums]
----
monaco.editor.defineTheme('corp-dark', {
  base: 'vs-dark',
  inherit: true,
  rules: [
    { token: 'comment', foreground: '6A9955', fontStyle: 'italic' },
    { token: 'keyword', foreground: 'C586C0' },
    { token: 'number.date', foreground: 'B5CEA8' }
  ],
  colors: {
    'editor.background': '#1E1E1E',
    'editorLineNumber.foreground': '#858585',
    'editor.lineHighlightBackground': '#2A2D2E'
  }
})

monaco.editor.setTheme('corp-dark')
----

内置主题为 `vs`, `vs-dark`, `hc-black`, `hc-light`. `setTheme` 是**全局**操作, 会影响页面上所有编辑器实例; 构造选项中的 `theme` 在创建时生效, 之后切换需调用 `setTheme`.

TIP: 系统处于高对比模式时, Monaco 默认会覆盖主题; 需要保持自定义配色时设置 `autoDetectHighContrast: false`.

[[monaco-perf]]
=== 性能与体积

以 Vite 7.3 生产构建实测 (未做 `manualChunks`), 主包体积如下:

[cols="4,2,2"]
|===
|引入方式
|主包
|gzip

|`import * as monaco from 'monaco-editor'`
|4.14 MB
|1.07 MB

|按需功能 + 单个 TypeScript 语言服务
|3.43 MB
|888 kB

|===

差距有限, 因为编辑器内核本身占大头; 按需注册削减的是功能贡献与语言定义. 真正的首屏优化手段是**延迟加载**与**拆包**:

* **延迟加载:** 编辑器通常不在首屏, 用动态 `import()` 在打开面板时加载, 先渲染骨架
* **独立分包:** 把 Monaco 拆到单独 chunk, 利用长缓存; worker 已经是独立产物
* **按语言注册:** 只引入用到的 `languages/definitions/<language>/register`, 避免 `register.all`
* **复用模型:** 切换文件用 `setModel`, 不要重建编辑器
* **及时释放:** 释放编辑器, 模型, 以及 provider 返回的 `IDisposable`
* **大文件参数:** `largeFileOptimizations` 默认开启, 超长单行可调低 `maxTokenizationLineLength`, 并谨慎开启 `wordWrap`
* **渲染节流:** 批量更新用 `decorations.set()` 一次替换, 避免逐条操作

按需注册的写法:

[source,typescript,linenums]
----
import * as monaco from 'monaco-editor/editor'      // <1>
import 'monaco-editor/features/codeEditor/register'
import 'monaco-editor/features/find/register'
import 'monaco-editor/features/suggest/register'
import 'monaco-editor/features/hover/register'
import 'monaco-editor/languages/definitions/javascript/register'
import { typescriptDefaults }
  from 'monaco-editor/languages/features/typescript/register'

typescriptDefaults.setEagerModelSync(true)

const editor = monaco.editor.create(container, { language: 'typescript' })
----

<1> 子入口只导出编辑器与语言 API; 功能与语言都需要显式注册, 语言服务的配置对象以命名导出提供, 不再挂在 `monaco.<语言>` 上

[[monaco-pitfall]]
=== 常见问题

[cols="3,3,4"]
|===
|现象
|原因
|处理

|控制台报 "Could not create web worker"
|未注册 `MonacoEnvironment.getWorker`
|按打包器正确导入 worker 入口

|worker 404
|打包器未输出 worker 文件
|检查 `?worker` 后缀与构建产物

|编辑器空白或高度为 0
|容器无高度, 或创建时容器隐藏
|给容器固定高度, 显示后调用 `editor.layout()`

|语言服务不生效
|worker 的 `label` 未匹配
|覆盖 `json`, `css`, `scss`, `less`, `html`, `handlebars`, `razor`, `typescript`, `javascript`

|打包报 "Failed to resolve entry"
|使用了 0.56 之前的深路径
|改用 `monaco-editor/editor` 等新入口

|服务端渲染报 "document is not defined"
|编辑器依赖 DOM
|动态导入并禁用 SSR

|切换主题影响全部编辑器
|`setTheme` 是全局操作
|在应用层统一管理主题

|内存持续增长
|未释放编辑器, 模型或 provider
|逐项 `dispose`, 用 `getModels()` 排查

|===

React 项目常用 `@monaco-editor/react` (4.7.0), 默认从 CDN 加载, 内网或离线环境需要指向本地包:

[source,tsx,linenums]
----
import Editor, { loader } from '@monaco-editor/react'
import * as monaco from 'monaco-editor'

loader.config({ monaco })      // <1>

export function CodePanel() {
  return (
    <Editor
      height="60vh"
      defaultLanguage="typescript"
      defaultValue="const answer: number = 42;"
      onMount={(editor) => console.log(editor.getValue())}
    />
  )
}
----

<1> 使用本地包后仍需按前文注册 worker, 否则语言服务不可用

NOTE: Next.js 等框架在服务端预渲染时没有 `document`, 需要 `dynamic(() => import('./CodePanel'), { ssr: false })`.

[[monaco-summary]]
=== 总结

* Monaco Editor 是 VS Code 编辑内核的浏览器发行版, 强项是编辑体验与开箱语言服务, 代价是体积与打包复杂度
* 模型与视图分离: 共享模型即可实现多视图同步, 释放顺序是先编辑器后模型
* 0.53 起官方只支持 ESM; 0.56 起入口按功能与语言拆分, worker 必须显式注册且使用新路径
* 语言能力分三层: Monarch 着色, worker 语言服务, provider 扩展; 跨语言统一能力接入 LSP
* 体积优化靠延迟加载与按需注册, 单纯更换打包器收益有限
