[[javascript-defineproperty]]
== Javascript defineProperty方法讲解

对象属性的行为远不止"有一个值"这么简单: 它是否可写, 能否被 for...in 枚举, 能否被删除, 读写时是否要走自定义逻辑, 都由**属性描述符**决定. 普通赋值只能创建特性全为 true 的属性, 一旦需要只读字段、隐藏字段或读写拦截, 就必须回到 ES5 提供的 **Object.defineProperty** 上. 它也是 getter/setter 向下兼容、对象冻结、polyfill 与 Vue 2 响应式的共同底座.

参考: <<Web/JavaScript call、apply、bind 原理讲解.adoc#, JavaScript call、apply、bind 原理讲解>>, <<Web/JavaScript数据类型.adoc#, JavaScript数据类型>>

[[defineproperty-purpose]]
=== 核心作用: 精确控制属性的行为

给对象添加属性最直观的写法是 obj.name = 'Alice', 但这只能创建一个**普通的数据属性**: 可读、可写、可枚举、可删除. Object.defineProperty 则允许我们**直接描述属性本身的行为**:

[source, javascript]
----
Object.defineProperty(obj, prop, descriptor);
----

它在 obj 的**自有属性**上定义(或重新定义)名为 prop 的属性, 由 descriptor 指定该属性是否可写、是否可枚举、是否可配置, 以及它是数据属性还是访问器属性. 该 API 由 ES5 引入, 是 getter/setter、对象冻结、Vue 2 响应式等机制的底层手段, 返回值就是传入的 obj.

[[defineproperty-descriptor]]
=== 属性描述符 (Property Descriptor)

描述符分为两类, 同一次调用中混用会直接抛 TypeError: **数据描述符**只描述"值", **访问器描述符**只描述"读写行为".

[cols="1,4"]
|===
|字段|说明

|value|数据描述符特有, 属性的值; 缺省为 undefined
|writable|数据描述符特有, 能否通过赋值修改 value; 缺省为 false
|get|访问器描述符特有, 读取属性时调用的函数; 缺省为 undefined
|set|访问器描述符特有, 写入属性时调用的函数; 缺省为 undefined
|enumerable|公共字段, 能否被 for...in、Object.keys、JSON.stringify 等枚举; 缺省为 false
|configurable|公共字段, 能否被删除、能否重新定义、能否在数据属性与访问器属性之间转换; 缺省为 false
|===

NOTE: 定义**新**属性时, 没有写出的字段取 false / undefined, 而不是普通赋值时的 true; 重新定义**已有**属性时, 没有写出的字段则保持原值.

[cols="2,2,2"]
|===
|字段|普通赋值 obj.x = 1|defineProperty 只给 value

|value|1|1
|writable|true|**false**
|enumerable|true|**false**
|configurable|true|**false**
|===

也就是说, 只在描述符里写一个 value, 得到的属性会"看不见"(不可枚举)、"写不动"(不可写)、"删不掉"(不可配置), 这是最常见的踩坑点.

[[defineproperty-usage]]
=== 基本用法

==== 定义新属性

[source, javascript]
----
const user = {};

Object.defineProperty(user, 'id', {
  value: 1001,
  writable: false,
  enumerable: true,
  configurable: false
});

console.log(user.id);            // 1001
console.log(Object.keys(user));  // [ 'id' ]

user.id = 1002;                  // 静默失败(严格模式下抛 TypeError)
delete user.id;                  // 静默失败
console.log(user.id);            // 1001
----

defineProperty 只作用于**当前对象自身**, 不会沿着原型链查找. 即使原型上已有同名属性, 也会在自身新建一个自有属性把它**遮蔽**掉; 反过来, 想修改原型上的属性, 必须把 defineProperty 用在原型对象上.

==== 定义 getter / setter

[source, javascript]
----
const person = {
  firstName: 'Ada',
  lastName: 'Lovelace'
};

Object.defineProperty(person, 'fullName', {
  enumerable: true,
  configurable: true,
  get() {
    return this.firstName + ' ' + this.lastName;
  },
  set(value) {
    [this.firstName, this.lastName] = value.split(' ');
  }
});

person.fullName = 'Grace Hopper';
console.log(person.firstName, person.lastName); // Grace Hopper
console.log(Object.keys(person));               // [ 'firstName', 'lastName', 'fullName' ]
----

get/set 中的 this 指向**真正被访问的那个对象**. 例如通过 Object.create 继承这个访问器后再读取, this 是子对象, 而不是定义访问器的 person.

==== 修改已有属性的特性

[source, javascript]
----
const config = { debug: true, verbose: false };

// 只改 writable, 其余特性保持原值(仍是可枚举、可配置)
Object.defineProperty(config, 'debug', { writable: false });

config.debug = false;   // 被忽略
delete config.verbose;  // verbose 仍是可配置的, 可以删除
----

[[defineproperty-redefine]]
=== 重新定义的规则

defineProperty 能否成功, 取决于目标属性当前的 configurable 与 writable:

[cols="2,4"]
|===
|属性当前状态|允许的修改

|configurable: true|任意修改, 包括数据属性与访问器属性互转, 也可以删除后重建
|configurable: false|不能修改 configurable 和 enumerable, 不能在数据属性与访问器属性之间转换
|configurable: false, writable: true|可以把 writable 改成 false, 也允许继续修改 value
|configurable: false, writable: false|不能再改 value, 唯一合法的操作是用相同的值再定义一次
|===

失败时 Object.defineProperty 会直接抛 TypeError(注意与普通赋值在非严格模式下静默失败不同). 如果希望拿到布尔结果而不抛异常, 用 Reflect.defineProperty:

[source, javascript]
----
const obj = {};
Object.defineProperty(obj, 'x', { value: 1 });

Reflect.defineProperty(obj, 'x', { value: 2 });  // false, 不抛异常

try {
  Object.defineProperty(obj, 'x', { value: 2 }); // TypeError
} catch (e) {
  console.log(e.message);
}
----

[[defineproperty-internals]]
=== 底层原理: 属性表与内部方法

在 ECMAScript 规范中, 对象可以理解成一张**属性表**, 每一项对应一个描述符(内部用 \[[Value]]、\[[Writable]]、\[[Enumerable]]、\[[Configurable]] 或 \[[Get]]、\[[Set]] 表示). a.b 这样的读写操作并不是直接访问内存字段, 而是调用对象的一组内部方法:

[cols="1,3"]
|===
|内部方法|作用

|\[[GetOwnProperty]]|返回自有属性的描述符, 供 getOwnPropertyDescriptor 等使用
|\[[DefineOwnProperty]]|定义或修改自有属性, defineProperty 最终落在这里
|\[[Get]] / \[[Set]]|读取/写入属性, 前者沿原型链查找并调用 getter, 后者调用 setter 或写入数据属性
|\[[Delete]]|删除属性, delete 运算符落在这里
|===

于是 Object.defineProperty 的执行流程可以概括为:

. 校验 obj 是对象(对原始值调用会抛 TypeError), 把 prop 转成字符串或 Symbol
. 校验描述符的合法性: 数据字段与访问器字段不能同时出现, get/set 必须是函数或 undefined
. 补全缺省字段, 然后调用 obj.\[[DefineOwnProperty]](prop, descriptor)
. 结果为 false 时抛 TypeError, 否则返回 obj

普通对象使用默认实现, 而数组、TypedArray、String、arguments、Proxy 等**异质对象**会重写 \[[DefineOwnProperty]], 这正是它们行为特殊的原因:

* 数组定义索引属性时会同步更新 length; 如果把索引定义成非数字属性, length 不会缩短.
* 数组的 length 本身是不可配置属性, 只能改值或把它改成不可写, 不能删除.
* Proxy 会触发 handler 中的 defineProperty 陷阱, 返回值决定操作是否成功.

[[defineproperty-vue2]]
=== 典型应用: Vue 2 的响应式原理

Vue 2 用 Object.defineProperty 把普通对象"改造"成响应式对象: 每个属性被替换成 getter/setter, 读取时收集依赖, 写入时派发更新.

[source, javascript]
----
let currentWatcher = null;   // 简化: 真实实现中是 Dep.target

function defineReactive(obj, key, val) {
  const watchers = [];       // 简化: 真实实现中是 Dep 实例

  Object.defineProperty(obj, key, {
    enumerable: true,
    configurable: true,
    get() {
      if (currentWatcher) watchers.push(currentWatcher);  // 收集依赖
      return val;
    },
    set(next) {
      if (Object.is(next, val)) return;
      val = next;
      watchers.forEach(watcher => watcher.update());      // 派发更新
    }
  });
}
----

这种方案的局限也直接来自 defineProperty 的语义:

* 只能劫持**已经存在**的属性, 因此新增/删除属性不会触发 setter, Vue 2 需要 Vue.set / Vue.delete 手动补一次 defineReactive.
* 无法天然监听数组下标赋值, 只能改写数组原型上的 push、pop、splice 等方法.
* 不支持 Map、Set 等集合类型, 因为它们的元素不通过属性访问.
* 初始化时要递归遍历所有属性, 数据量大时有明显开销.

Vue 3 改用 Proxy 拦截 \[[Get]] / \[[Set]] / \[[Delete]] 等内部方法, 上述问题大多迎刃而解.

[[defineproperty-scenarios]]
=== 常见应用场景

. **定义真正的常量**
+
writable: false 与 configurable: false 一起使用, 赋值和删除都会失败, 比 const 更严格(const 只约束变量绑定, 不约束对象属性).

. **隐藏内部字段**
+
enumerable: false 的字段不会被 for...in、Object.keys、JSON.stringify 看到, 常用来存放库或框架的内部状态; 再配合 Symbol 作为键名, 可以做到"既不枚举、也不容易撞名".

. **给内置原型打补丁 (polyfill)**
+
[source, javascript]
----
// enumerable 缺省为 false, 不会污染 for...in
Object.defineProperty(Array.prototype, 'last', {
  value: function() { return this[this.length - 1]; },
  writable: true,
  configurable: true
});
----

. **对象冻结与密封的底层实现**
+
Object.freeze 本质上就是对每个自有属性调用 defineProperty: 数据属性改成 writable: false, 所有属性改成 configurable: false; Object.seal 只做后者.

. **控制序列化结果**
+
JSON.stringify 只序列化可枚举的自有属性, 把敏感字段或缓存字段设为不可枚举即可从序列化结果中排除, 同时不影响代码内部读取.

. **拦截读写做校验、日志或惰性计算**
+
[source, javascript]
----
const state = {};

Object.defineProperty(state, 'report', {
  enumerable: true,
  configurable: true,
  get() {
    if (!this._report) this._report = buildExpensiveReport();
    return this._report;
  },
  set(value) {
    if (typeof value !== 'object') throw new TypeError('report 必须是对象');
    this._report = value;
  }
});
----

[[defineproperty-api]]
=== 配套 API

[cols="2,4"]
|===
|API|说明

|Object.getOwnPropertyDescriptor(obj, key)|读取单个自有属性的描述符, 属性不存在或不自有时返回 undefined
|Object.getOwnPropertyDescriptors(obj)|读取全部自有属性的描述符, 常与 Object.create / Object.defineProperties 配合做保留特性的拷贝
|Object.defineProperties(obj, descriptors)|一次定义多个属性, 内部逐个执行 defineProperty
|Object.create(proto, descriptors)|创建对象的同时定义属性, 常用于"以某对象为原型并追加访问器"
|Reflect.defineProperty(obj, key, desc)|与 defineProperty 语义一致, 但不抛异常, 返回布尔值
|Object.freeze / Object.seal / Object.preventExtensions|内部按描述符修改属性特性
|new Proxy(target, { defineProperty })|拦截 defineProperty 调用, 可以校验或改写描述符
|===

[[defineproperty-pitfall]]
=== 注意事项

* **访问器描述符不能带 value / writable**, 否则抛 TypeError; 反之数据描述符也不能带 get / set.
* **defineProperty 不受原型链限制.** 普通赋值遇到原型上的只读属性会失败, 而 defineProperty 可以在自有属性上直接遮蔽它.
* **不要用 defineProperty 改原型.** 对 +__proto__+ 使用 defineProperty 只会在实例上创建一个同名自有数据属性, 并不会改变原型; 修改原型请用 Object.setPrototypeOf 或 Object.create.
* **不可配置是不可逆的.** 属性一旦被定义为 configurable: false, 就永远无法删除或改回可配置; 在全局对象(如 window)上要格外小心, 否则很容易把自己锁死.
* **字面量与类中的访问器特性不同.** 对象字面量里的 get/set 是**可枚举**的, 而 class 中的访问器定义在原型上且**不可枚举**; 需要统一行为时用 defineProperty 显式指定.
* **对性能敏感的场景要谨慎.** 频繁用 defineProperty 动态添加属性会让 V8 的隐藏类(shape)频繁变化, 甚至退化为字典模式(慢属性), 使内联缓存失效; 热点路径上优先用对象字面量或 Map.
* **严格模式行为不同.** 修改失败时, Object.defineProperty 一定抛异常; 而普通赋值只在严格模式下抛异常, 非严格模式下静默失败.

[[defineproperty-summary]]
=== 总结

* Object.defineProperty 的价值不在于"加属性", 而在于**精确描述属性的特性**: 可写性、可枚举性、可配置性, 以及用 get/set 接管读写.
* 缺省值全为 false 是它与普通赋值最大的差异, 也是绝大多数 bug 的来源.
* 重新定义受 configurable / writable 双重约束, 且不可逆, 使用时先想清楚属性的最终形态.
* 它是 getter/setter 劫持、对象冻结、polyfill、Vue 2 响应式的共同底座; 理解了 \[[DefineOwnProperty]] 这层内部方法, 也就理解了这些特性的边界.
