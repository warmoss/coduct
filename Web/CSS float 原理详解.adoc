== CSS float 原理详解

**float** 是 CSS 中一个非常重要的布局属性, 最初的设计目的是为了实现文字环绕图片的效果, 后来被广泛用于多列布局. 尽管现代布局(如 Flexbox 和 Grid)已经能更优雅地完成类似任务, 但理解 float 的原理仍然是掌握 CSS 布局的核心基础.

=== 基本概念: 文档流与浮动

在普通文档流(Normal Flow)中, 块级元素(如 div、p)会从上到下垂直排列, 每个元素独占一行; 内联元素(如 span、img)则会从左到右水平排列, 直到行框占满才换行.

**当元素被设置为 float 后, 它会:**

* 脱离普通文档流, 但**不完全脱离文本流**(文本和行内元素会"环绕"它)

* 沿着父容器左侧或右侧移动, 直到碰到父容器边框、内边距或另一个浮动元素的边缘

* 浮动元素的宽度默认由内容撑开(可以设置固定宽度)

* 浮动元素仍然占据父容器的空间(对布局的影响体现在高度塌陷)

=== 浮动带来的视觉变化

假设有一个 img 左浮动, 那么它周围的文字(或行内元素)**会自动排列在它的右侧**, 形成环绕效果. 这是因为浮动元素让出了自己旁边的空间, 行框(Line Box)会被缩短, 给浮动元素腾出位置.

[source, css]
----
img {
  float: left;
  margin-right: 10px;
}
----

此时, 图片左侧靠父容器左边, 右侧的文字则紧贴图片的右边框(加上外边距), 直到文字高度超过图片时, 才重新填满整个行宽.

=== 浮动的详细规则

根据 W3C 规范, 浮动元素的行为遵循以下主要规则:

. **浮动元素会生成一个块级框**
+
即使元素本身是内联元素(如 span), 一旦设置 float, 它的 display 计算值就会变为 block(或类似块级特性), 可以设置宽高、内外边距.

. **浮动元素的定位**

** 左浮动元素会尽可能向左上移动, 右浮动元素尽可能向右上移动.

** 多个浮动元素会一个接一个地排列, 直到一行放不下时换行.

** 浮动元素不能超出包含块的边界, 也不能高于它前面浮动元素(或块级元素)的顶部(除非有负外边距等特殊情况).

. **浮动不会覆盖普通文档流中的文本和行内元素**
+
块级元素会无视浮动元素(占据一整行), 但块级元素内的文本和行内元素会环绕浮动元素. 这也是为什么父容器高度会塌陷: 块级元素(父容器)计算高度时, 不考虑浮动的子元素.

. **外边距不会合并**
+
相邻浮动元素之间的垂直外边距不会合并(不像普通块级元素那样).

=== 父容器高度塌陷的原因

当父容器内部只有浮动子元素时, 父容器的高度会变成 0(因为浮动元素脱离文档流, 不参与父容器的高度计算). 这会导致布局错乱, 比如父容器背景无法包裹浮动元素, 后续元素可能挤占浮动元素的位置.

**解决办法: 清除浮动**

通过 clear 属性或触发 BFC(块格式化上下文)来让父容器重新包裹浮动元素.

* **使用 clear**

在父容器末尾添加一个空元素(如 <div style="clear:both;"></div>), 或使用伪元素:

[source, css]
----
.clearfix::after {
  content: "";
  display: table; /* 或者 block */
  clear: both;
}
----

* **触发 BFC**

设置父容器 overflow: hidden 或 display: flow-root(现代方法)可以让父容器计算高度时包含浮动元素.

=== 浮动的经典用途与替代方案

* **文字环绕**(原设计目的, 至今仍是最合适的场景)

* **多列布局**(如两列自适应, 左边固定宽浮动, 右边用 margin-left 避开浮动)

* **导航菜单水平排列**(将 li 浮动, 但现代用 Flex 更好)

**现代替代方案:**

* Flexbox: 适合一维布局(行或列)

* Grid: 适合二维布局(网格)

* 对于简单环绕效果, float 仍然无法被替代.

=== 总结

* float 让元素脱离文档流但保留对文本的影响.

* 它会导致父容器高度塌陷, 需要清除浮动.

* 浮动元素会沿着父容器左右排列, 多个浮动会依次排列.

* 理解浮动的原理能帮助你更好地调试旧代码, 并为学习更高级布局打下基础.
