== HTTP常见状态码讲解

HTTP 状态码是服务器对客户端请求的响应的重要组成部分, 它们以三位数字代码的形式告诉我们请求是成功了、失败了, 还是需要进一步操作.

这些状态码被分为五个类别, 以第一个数字开头:

* **1xx (信息性状态码):** 请求已被接收, 继续处理.

* **2xx (成功状态码):** 请求已成功被服务器接收、理解并接受.

* **3xx (重定向状态码):** 需要客户端采取进一步的操作才能完成请求.

* **4xx (客户端错误状态码):** 客户端似乎发生了错误, 请求包含语法错误或无法完成.

* **5xx (服务器错误状态码):** 服务器在处理请求时发生了错误.

下面我们来详细讲解一些最常见和重要的状态码.

=== 1xx - 信息性状态码

这类状态码比较少见, 通常表示请求已被接收, 正在处理.

* **100 Continue:** 客户端应继续发送请求的剩余部分. 通常用于客户端先发送一个请求头, 询问服务器是否愿意接收一个大的请求体.

* **101 Switching Protocols:** 客户端要求服务器切换协议, 服务器已同意切换. 例如, 从 HTTP 切换到 WebSocket.

=== 2xx - 成功状态码

这类状态码表示请求已成功处理.

* **200 OK:** 最常见的成功状态码. 请求成功, 响应报文中包含请求的结果. 对于 GET 请求, 资源已返回; 对于 POST 请求, 操作已完成.

* **201 Created:** 请求已成功, 并因此创建了一个新的资源. 这通常是在 POST 或 PUT 请求之后发送的响应. 响应头 Location 字段通常会包含新资源的 URL.

* **202 Accepted:** 请求已被接受, 但尚未处理完成. 适用于异步任务, 比如一个需要长时间运行的处理请求, 服务器先接受, 后续再处理.

* **204 No Content:** 服务器成功处理了请求, 但不需要返回任何实体内容. 例如, 对于 DELETE 请求, 或者提交表单后不需要跳转页面的情况.

=== 3xx - 重定向状态码

这类状态码告诉客户端需要执行额外的操作(通常是再次发起一个请求到不同的 URL)来完成请求.

* **301 Moved Permanently:** 永久重定向. 请求的资源已被永久移动到新的 URL. 客户端应该使用新的 URL 进行以后的请求. 搜索引擎会将权重转移到新URL.

* **302 Found:** 临时重定向. 请求的资源临时从不同的 URL 响应. 客户端应该继续使用原始 URL 进行以后的请求. 这是最常见的重定向类型.

* **304 Not Modified:** 资源未改变. 用于客户端缓存. 当客户端在请求头中提供了 If-Modified-Since 或 If-None-Match 等信息时, 如果服务器判断资源在此期间没有被修改, 就会返回 304, 告诉客户端直接使用本地缓存. 这不是一个错误, 而是为了节省带宽和提升性能.

=== 4xx - 客户端错误状态码

这类状态码表示错误似乎是客户端引起的.

* **400 Bad Request:** 错误的请求. 服务器无法理解请求的格式, 通常是由于语法错误(如参数错误、请求体格式错误)导致的.

* **401 Unauthorized:** 未认证. 请求需要用户认证. 客户端必须提供认证信息(如用户名和密码). 如果之前已经认证过, 则表示认证失败.

* **403 Forbidden:** 禁止访问. 服务器理解请求, 但拒绝执行. 与 401 不同, 403 表示客户端身份已得到验证, 但没有访问该资源的权限.

* **404 Not Found:** 最著名的错误码. 服务器找不到请求的资源. 这可能是由于 URL 拼写错误、资源已被删除或链接失效导致的.

* **405 Method Not Allowed:** 请求行中指定的请求方法不能被用于请求相应的资源. 例如, 对只支持 GET 的 URL 使用了 POST 方法.

* **408 Request Timeout:** 服务器等待客户端发送请求的时间过长, 超时了.

* **429 Too Many Requests:** 请求过多. 客户端在给定的时间内发送了太多请求("限速"或"速率限制").

=== 5xx - 服务器错误状态码

这类状态码表示服务器在处理请求时发生了错误.

* **500 Internal Server Error:** 最常见的服务器错误. 服务器遇到了一个未曾预料的状况, 导致了它无法完成对请求的处理. 这是一个笼统的错误码, 通常意味着服务器端应用程序代码出了 bug.

* **502 Bad Gateway:** 错误的网关. 当服务器作为网关或代理, 从上游服务器(如应用服务器)收到无效响应时, 返回此错误.

* **503 Service Unavailable:** 服务不可用. 服务器当前无法处理请求(由于超载或系统停机维护). 这通常是临时状态. 响应中可能包含 Retry-After 头, 告知客户端多久后可以重试.

* **504 Gateway Timeout:** 网关超时. 当服务器作为网关或代理, 未能及时从上游服务器收到响应时, 返回此错误.

=== 记忆技巧与总结

[cols="2,2,3,4"]
|===
|状态码|类别|口诀/解释|常见场景

|200|成功|OK, 一切正常|页面或资源加载成功
|301/302|重定向|永久搬走/临时外出|URL 跳转, 旧链接指向新地址
|304|重定向|没变, 用缓存|刷新页面, 但资源未更新
|400|客户端错误|你发的东西我看不懂|请求参数格式错误
|401|客户端错误|你是谁?|未登录访问需要登录的页面
|403|客户端错误|我知道你是谁, 但你不能进|登录了但权限不足
|404|客户端错误|你要的东西找不到|点击了失效的链接, URL拼错
|429|客户端错误|你刷得太快了|API 调用过于频繁被限制
|500|服务器错误|我(服务器)内部出错了|后端代码有 Bug, 数据库连接失败
|502|服务器错误|我后面的服务挂了|Nginx 后面的 PHP/Java 服务崩溃
|503|服务器错误|我太忙了, 等会再来|服务器维护或流量过大
|504|服务器错误|我等后面服务等太久了|后端服务响应超时
|===
