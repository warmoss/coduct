== JavaScript call、apply、bind 原理讲解

=== 核心作用: 动态改变 this 指向

JavaScript 中, 函数的 this 指向通常由调用方式决定(如默认绑定、隐式绑定、显式绑定、new 绑定). call、apply、bind 是**显式绑定**的三种手段, 它们都能改变函数执行时的 this 值.

=== 基本用法与区别

[cols="3,2,2,2"]
|===
|方法|参数形式|执行时机|返回值
|fn.call(thisArg, arg1, arg2, ...)|逐个传递参数|立即执行|函数执行结果
|fn.apply(thisArg, [argsArray])|参数以数组(或类数组)形式传递|立即执行|函数执行结果
|fn.bind(thisArg, arg1, arg2, ...)|逐个传递参数(可预设部分参数)|返回一个新函数, 不会立即执行|绑定了 this 的新函数
|===

[source, javascript]
----
function greet(greeting, punctuation) {
  console.log(greeting + ', ' + this.name + punctuation);
}

const person = { name: 'Alice' };

greet.call(person, 'Hello', '!');     // Hello, Alice!
greet.apply(person, ['Hi', '?']);     // Hi, Alice?
const boundGreet = greet.bind(person, 'Hey');
boundGreet('.');                      // Hey, Alice.
----

=== 底层原理: this 是如何被改变的?

要理解原理, 需要明白: **函数内部的 this 是由调用时的上下文决定的.** 当调用 fn.call(obj) 时, JavaScript 引擎会做类似下面的事情:

. 将 fn 临时作为 obj 的一个属性(比如 obj.tempFn = fn)

. 执行 obj.tempFn() —— 此时隐式绑定规则让 this 指向 obj

. 执行结束后删除这个临时属性

. 返回函数执行结果

apply 与 call 原理相同, 只是参数处理方式不同.

bind 则更复杂: 它返回一个**包装函数**(bound function), 这个包装函数内部通过 call 或 apply 来调用原函数, 并固定 this 和部分参数(偏函数). 即使后来用 new 调用这个 bound 函数, this 也会被忽略(但原函数的原型链会被保留).

=== 手写实现(彻底理解原理)

==== 手写 call

[source, javascript]
----
Function.prototype.myCall = function(context, ...args) {
  // 如果 context 是 null/undefined, 则指向全局对象(浏览器中为 window, Node 中为 global)
  // 原始值会被包装成对象(例如 123 → Number 实例)
  context = context == null ? globalThis : Object(context);
  
  // 用 Symbol 保证属性名唯一, 避免覆盖原有属性
  const fnKey = Symbol('temp');
  context[fnKey] = this;  // this 就是调用 myCall 的函数
  
  // 执行函数并收集结果
  const result = context[fnKey](...args);
  
  // 清理临时属性
  delete context[fnKey];
  
  return result;
};
----

==== 手写 apply

[source, javascript]
----
Function.prototype.myApply = function(context, argsArray) {
  context = context == null ? globalThis : Object(context);
  const fnKey = Symbol('temp');
  context[fnKey] = this;
  
  let result;
  if (argsArray) {
    // 注意: apply 第二个参数可以是数组或类数组, 但需确保是可迭代的
    result = context[fnKey](...argsArray);
  } else {
    result = context[fnKey]();
  }
  
  delete context[fnKey];
  return result;
};
----

==== 手写 bind(基础版, 支持 new 的完整版较复杂)

[source, javascript]
----
Function.prototype.myBind = function(context, ...boundArgs) {
  const originalFn = this;
  
  function boundFn(...callArgs) {
    // 关键: 如果 boundFn 被作为构造函数调用(即通过 new), 则 this 指向新实例, 不应该被 context 覆盖
    // 判断方式: 检查 this 是否是 boundFn 的实例(即 this instanceof boundFn)
    const finalContext = this instanceof boundFn ? this : context;
    return originalFn.apply(finalContext, [...boundArgs, ...callArgs]);
  }
  
  // 维护原型链: 如果原函数有 prototype, 则 boundFn 也要继承它
  if (this.prototype) {
    boundFn.prototype = Object.create(this.prototype);
  }
  
  return boundFn;
};
----

**更严谨的 bind 要点:**

* 返回的函数可以作为构造函数(new boundFn())调用, 此时 this 指向新对象, 预设参数依然有效.

* 需要处理 context 为 null/undefined 时指向全局.

* 返回的函数拥有 length 属性(原函数参数个数减去已绑定的参数个数), 但手写难以完美模拟.

=== 常见应用场景

. **借用方法**
+
[].slice.call(arguments) 把类数组转成真数组.

. **继承**
+
在构造函数中 Parent.call(this) 调用父类构造.

. **柯里化与偏函数**
+
bind 可以固定部分参数, 返回新函数.

. **事件处理器中保留 this**
+
this.handleClick.bind(this) 确保回调中的 this 指向组件实例.

=== 易混淆点

* call/apply 立即执行, bind 返回新函数.

* bind 绑定的函数, 即使多次 bind, 也只有第一次绑定生效(因为 bind 内部已固化 this).

* 箭头函数无法通过 call/apply/bind 改变 this, 其 this 由定义时的词法作用域决定.

=== 总结

* 三者本质都是利用**对象属性临时存储函数并调用**的机制来重设 this.

* call/apply 适合一次性改变 this 并执行; bind 适合持久绑定, 尤其适合回调或事件监听.

* 手写实现能帮助理解作用域链、原型链、new 操作符等底层概念.

掌握这些原理后, 不仅能正确使用它们, 还能轻松阅读源码中大量出现的 fn.call(this, ...) 模式.
